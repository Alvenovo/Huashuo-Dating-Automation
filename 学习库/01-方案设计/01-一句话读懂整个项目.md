# 01 · 一句话读懂整个项目

> **预计阅读 6 分钟** · 这是全库的**起点**，先读这篇，别急着看细节

---

## 🎯 一句话版

**在一台 Windows 电脑上，写一套程序，让它自动去点「华硕大厅」这个软件，检查每一版能不能用。**

```
人工做的话：              自动化做的话：
  打开电脑                  程序自动：
  装软件 → 看版本            装软件 → 读版本 → 启动 → 点搜索 → 看结果
  点开软件 → 点搜索          跑完给你一份报告：哪步过了，哪步挂了
  一条条手动验
  （每次半小时以上）        （十几分钟，不用人管）
```

---

## 📖 阅读前 · 2 个名词先搞懂

### 名词 1：自动化测试

**大白话**：把"人工点软件检查"这件事，**写成程序让电脑自己点**。

**类比**：你原来要**亲口尝每道菜**判断咸淡；现在找了个**机器舌头**，它替你尝，还能打印出"盐度 2.3%"这种准确数字。

> [!tip] 为什么不能全靠人工
> 因为发版频繁。每出一版都人工验一遍，**人力扛不住，而且人会疲劳、会漏**。

### 名词 2：冒烟测试（Smoke Test）

**大白话**：**只测最关键的几步**，快速回答"这东西还能不能用"。

**类比**：**体检先量血压体温** —— 不查全身，但能快速判断"有没有大问题"。

> [!important] 「冒烟」这个名字的来源
> 源自硬件行业：**新电路板通电，先看冒不冒烟**。不冒烟 = 基本能用，可以继续测；冒烟 = 直接别测了，先修。
> 所以"冒烟测试"的定位就是：**快速、粗糙、只筛大问题**。

---

## 🔺 三个必须同时成立的事实

> **这三条是"地基"。整套方案的每一个设计选择，都能追溯到这三条之一。**
> 所以：**先记这三条，其余的可以推出来。**

### 事实 ①：客户端是「两层楼」结构

```
┌─────────────────────────────┐
│   外壳层（WPF）              │  ← 原生 Windows 控件
│   ┌─────────────────────┐   │
│   │  内页层（WebView2）  │   │  ← 里面是个浏览器，跑网页
│   │  搜索、详情、活动页  │   │
│   └─────────────────────┘   │
└─────────────────────────────┘
```

**为什么重要**：两层楼的**操作方式不同**，所以测试手段要**分层**。

**类比**：这栋楼**一楼是实体店，二楼是网店**。查一楼的货要问店员（A 方法），查二楼的货要上网站（B 方法）—— **不能拿查一楼的方法去查二楼**。

### 事实 ②：安装/卸载向导是「不挂招牌的摊位」（NSIS）

**为什么重要**：这类程序**不汇报自己的控件清单**，所以标准手段（UIA）**完全读不到**，必须换一套更底层的办法（Win32）。

→ 展开见 [[02-UIA为什么有时是瞎的]]

### 事实 ③：大厅里的应用列表**全是真软件**

微信、QQ、WPS、Python3…… **点一下"全部更新"就会真的把它们全升一遍。**

**为什么重要**：所以执行类操作必须**限定在安全对象上**，并且有**红线**禁止乱点。

> [!warning] 这条是最危险的
> 前两条是"技术难做"，第三条是"**做错了后果严重**"。
> 想象一下：你在办公机上跑测试，脚本顺手把微信卸了 —— 这不是玩笑。

## 🗺️ 全流程地图

```
① 安装包（一个 .exe 文件）
        │  ← 需要管理员权限
        ▼
② 注册表 + 文件版本 + 关于页     ← 三条路对照版本对不对
        │
        ▼
③ 启动大厅（进程跑起来，窗口出现）
        │
        ▼
④ 主窗口「华硕大厅」
        ├── 外壳控件  ──→ 能读到
        └── 内页控件  ──→ 也能读到
        │
        ▼
⑤ 搜索 → 详情                    ← P0 冒烟到这儿为止
        │
        ├── ⑥ 应用装卸（含 NSIS 向导 → 要换 Win32）      ← P1
        ├── ⑦ 账号（登录/短信/微软）                      ← P1
        └── ⑧ 设置（主题切换）                            ← P1
        │
        └── ⑨ 会员 / 活动                                 ← P2 抽检
```

> [!important] 记住这个"漏斗形状"
> **越往上（①②③）越基础，坏了下面就全停；越往下越独立，坏了互不影响。**
> 这就是为什么 P0 只做 ⑤，而 ⑥⑦⑧⑨ 各自独立成包。

## 💡 最核心的一个思想：别点屏幕，去读档案

这是整套方案**最重要的一条**，值得单独想清楚。

要验证「装上了吗？版本对不对？」，有两条路：

| | 路 A：看屏幕 | 路 B：读档案 |
|---|---|---|
| **做法** | 打开控制面板 → 找到华硕大厅 → 看版本号 | 直接读系统注册表 + 读 exe 文件版本 |
| **依赖** | 控制面板能开、列表能滚、字体正常、没被遮挡…… | 只依赖系统本身 |
| **风险** | 任何一环抖动就失败 | 极低 |
| **类比** | **问店员"这货多少钱"**（他可能看错、可能不在） | **自己查账本** |

**方案选了 B。**

→ 展开见 [[03-为什么能读状态就不点UI]]

## 🧠 记忆卡（考前背这一页）

### 口诀 ①：**两层楼**

> 外壳层 + 内页层 = 两层楼。
> **一楼问店员，二楼看网站** —— 手段要分层。

### 口诀 ②：**档案室**

> 判断对错**别问店员，去查档案**。
> 屏幕可能骗你，系统档案不会。

### 口诀 ③：**真道具，别乱摔**

> 列表里全是真软件。
> **只有排练道具（夹具）能摔。**

### 三句串起来

```
① 两层楼      → 所以要分手段
② 档案室      → 所以要读系统，不看屏幕
③ 真道具      → 所以危险操作要圈定范围
```

## 🎤 应对提问

> [!question]- Q1：这个项目是做什么的？一句话。
> **给「华硕大厅」这个 Windows 客户端做自动化测试，回答"这个版本能不能发"。**
>
> 追问可以说：不是"功能全不全"，而是"**这版能不能用**"——所以只做最关键的冒烟流程，不追求全功能覆盖。

> [!question]- Q2：为什么叫"冒烟测试"？
> 源自硬件：**新电路板通电先看冒不冒烟**。
> 冒烟 = 直接别测了，先修；不冒烟 = 基本能用，可以继续。
> 含义就是**快速筛大问题**。

> [!question]- Q3：为什么要做自动化？人工不行吗？
> 三个原因：
> ① **发版频繁** —— 每版都人工验，人力扛不住
> ② **人会疲劳** —— 同样的操作做几十遍必然漏
> ③ **人给不出精确数字** —— 人只会说"版本好像不对"，程序能说"期望 1.6.11.4，实际 1.6.11.2"

> [!question]- Q4：这个客户端有什么特别的难点？
> 三个：
> ① **两层结构** —— 外壳和内页，操作方式不一样
> ② **装/卸向导不汇报控件** —— 标准手段读不到，要换底层办法
> ③ **列表全是真软件** —— 点错就真装/真卸
>
> ⚠️ **推断**：这三个难点里，③ 是"风险型"难点，①② 是"技术型"难点。
> 两者的应对逻辑不同 —— 前者靠**范围限制**，后者靠**换手段**。

> [!question]- Q5：如果让你给别人介绍这个项目，怎么讲最清楚？
> 推荐三段式：
> ① **是什么**：给华硕大厅客户端做的自动化冒烟测试
> ② **难在哪**：两层结构、向导不可读、列表是真软件（**这三条最能体现深度**）
> ③ **怎么做**：分层（P0/P1/P2）+ 读系统档案 + 夹具隔离
>
> ⚠️ **别一上来就讲控件名**（`SearchBarInput` 之类）—— 对方听不懂，而且会失去兴趣。
