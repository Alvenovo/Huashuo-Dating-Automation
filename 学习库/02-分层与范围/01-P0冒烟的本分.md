# 01 · P0 冒烟的本分

## P0 要回答的问题

> **「新包或日常回归时，十几分钟内告诉我这版能不能用。」**

注意"十几分钟"和"能不能用"，不是"功能对不对"。这个定位直接决定了 P0 只有 7 条。

## P0 七条一览

| 编号 | 能力 | 关键通过标准 |
|---|---|---|
| P0-01 | 安装基线包 | 无已装则装；已装则**先卸再装**。注册表显示名含「华硕大厅」，`DisplayVersion` = 包名去 `S` 的四段号，exe `FileVersion` 相同 |
| P0-02 | 升级到最新包 | 基线已装前提下跑更新包（覆盖安装），版本变为最新包去 `S` 的四段号 |
| P0-03 | 启动 | 进程起来，主窗口标题「华硕大厅」，已知首跑弹窗按配置自动同意 |
| P0-04 | 启动就绪 | 超时内从黑屏进可交互首页；**未知弹窗 = 失败**；连续冷启动 **3** 次；只比结构不比 Banner |
| P0-05 | 登录墙 | 若搜索/详情必须登录则账密登录，否则**跳过** |
| P0-06 | 搜索 | 配置关键词（默认 `qq`）返回列表，**至少两条**标题命中 |
| P0-07 | 详情 | 点进一条，详情页出现名称 + 安装/打开/更新类主按钮 |

## P0-04 是全篇最精妙的一条

组长反馈了两个问题：「刚进大厅黑屏后弹窗」「主界面有时显示不一致」。方案把它们**合并进 P0-04，不单独立项**，并且给了非常细的口径。这是"把模糊反馈转成可判定标准"的范例：

| 现象 | 口径 |
|---|---|
| **黑屏** | 允许短暂过渡；**超时仍全黑或 WebView 空白 = 失败** |
| **弹窗** | 白名单（协议/权限/已知更新提示）可点；**名单外失败并留证**；禁止盲点未知框 |
| **显示不一致** | 只比「结构是否就绪」（导航/内容区/搜索入口是否都在）；**不比 Banner 文案** |
| **身份差异** | 未登录 vs 已登录、会员 vs 非会员外观不同 → 走 P0-05 / P2，**不当 P0-04 缺陷** |
| **偶发** | P0-04 连续冷启动 3 次；要压 50 次过夜的**另开 P1 浸泡**，不塞进日常冒烟 |

> [!tip] 为什么"未知弹窗 = 失败"而不是"跳过"？
> 因为**未知弹窗可能正在问用户要不要装某个软件**。盲目跳过或盲点，风险不可控。
> 失败 + 截图 + 标题/正文留证，是把"我不知道这是什么"变成"有人能判断"的最短路径。

## 冷启动为什么是 3 次

一次通过可能是运气（缓存热、网络快）。连续 3 次结构完全一致，才排除了偶发。

但**没有升到 50 次**——那是"浸泡测试"的范畴，属于 P1 单独立项。这是"够用就好"的判断：日常冒烟要在十几分钟内出结果，压 50 次要跑通宵。

## P0 明确不做的事

- 短信、微软登录、注册、找回密码
- **真下载安装第三方应用**
- 主题、会员、活动页
- 像素级截图对比主界面

> [!warning] 一个容易混淆的点
> 「大厅**自身**卸载」属于 **P0-01 的前置**（因为它要给安装腾地方），**不算商店应用卸载**。
> 商店应用的装卸全是 P1-A 的事。

## 失败传播（P0 内部）

```
安装失败  → 后面全部跳过
启动失败  → UI 套件跳过，安装层结果仍保留
搜索失败  → 详情跳过，不影响「版本正确」
验证码未回填 → 记「阻塞」，不记产品缺陷
```

注意「搜索失败 → 版本正确仍算通过」这个设计：**它保留了已经拿到的有效结论**，而不是因为后面失败就否定前面。这比"一失败全红"更有信息量。

## 自测

> [!question]- Q1：为什么 P0-04 的"显示不一致"只有结构性判据？
> 因为**业务内容是易变运营数据**。Banner 天天换、活动随时上下线。如果把它们纳入判据，P0 会天天红，而红的原因与代码质量无关。
> 方案的选择：**P0 只保"产品还能用"的底线**，内容正确性交给 P2 抽检或人工。
> 这是主动缩小范围换稳定性——**不是覆盖不全，是分层合理**。

> [!question]- Q2：「未登录 vs 已登录首页长得不一样」为什么不算 P0-04 缺陷？
> 因为登录状态**本来就是产品设计的差异**，产品**应该**长得不一样。
> 把"符合预期的差异"报成缺陷，是自动化常见误区。方案把它归到 P0-05（登录墙）或 P2（会员身份）。
> **判据：差异是否由产品设计意图产生？是 → 不是缺陷。**

> [!question]- Q3：如果 P0-04 压 3 次都过，但用户说"我遇到过黑屏"，怎么办？
> 这不矛盾。3 次是**日常冒烟的置信度控制**，不是"证明不存在偶发"。
> 用户报的偶发问题应该：
> ① 先看证据（截图/标题/正文是否已知弹窗）；
> ② 需要压频次就**另开 P1 浸泡**（50 次过夜）；
> ③ 不要临时把 P0 改成 50 次——那会拖慢所有日常回归。
> **分层就是为了让不同目的的任务不互相拖累。**

> [!question]- Q4：P0-01 里"已装则先卸再装"为什么必要？
> 因为要保证**基线是干净的**。如果机器上已经装了更新版本，直接装旧包可能出现版本拒绝降级、残留配置影响首跑等干扰。
> 卸干净再装，才有确定的起点——这和测试里的"夹具复位"是同一个思路。

> [!question]- Q5：把 P0 的七条按"依赖关系"排一下序，哪条可以独立？
> 大体是 01 → 02 → 03 → 04 → (05) → 06 → 07 的链。
> 但注意 **P0-05 是可跳过的分支**（若无需登录），P0-06/07 依赖 04 就绪。
> **能独立的是 P0-01/02 的安装层**——它不需要起 UI，可以单独在专用机跑。
