# 02 · 为什么 UIA 有时是瞎的

> **预计阅读 9 分钟** · 全项目**最关键的一条技术认知**。理解它，就理解了一半的技术方案。

---

## 📖 阅读前 · 3 个名词先搞懂

### 名词 1：UIA（读作 "U-I-A"）

**全称**：UI Automation（界面自动化）

**大白话**：微软提供的一套"**无障碍接口**"。
它的工作方式是：**程序主动把自己的控件清单报出来**，UIA 去读这份清单。

**类比**：**问服务员要菜单**。
服务员（程序）愿意给你菜单，你才能点菜（操作控件）。**服务员不给，你就点不了。**

### 名词 2：Win32 API（读作 "win-32"）

**大白话**：更底层的一套接口。**不问程序，直接问系统**"这台机器上有哪些窗口、上面有什么"。

**类比**：**不进店问菜单，直接趴窗户上看，甚至进厨房翻**。
不依赖对方配合，**但能看到的也更粗糙**。

### 名词 3：NSIS（读作 "N-S-I-S"）

**大白话**：一种**做安装包的工具**。很多软件的"安装向导""卸载向导"都是它做的。

**本题的关键**：**用 NSIS 做的向导，不报控件清单。**

---

## 🎬 现象：UIA 给出了荒谬的报告

探针（一种专门用来"侦察"界面结构的工具）实测结果是：

```
UIA 报告：这个窗口里有 0 个控件
   ↑
明明屏幕上摆着「立即安装」「取消」「上一步」好几个按钮
UIA 说：里面什么都没有

而且更奇怪：它把每个按钮都误报成"独立的窗口"
   class 叫 Button / Edit / Static（这些是控件的类别名）
   但名字全是空的
```

> [!warning] 结果：两条常规路同时死掉
> | 常规做法 | 结果 |
> |---|---|
> | ① 按按钮名字找 | ❌ 名字是空的，找不到 |
> | ② 列出窗口里所有控件逐个找 | ❌ 报告说 0 个，没得找 |
>
> **两条路同时断，这就是"UIA 瞎了"。**

---

## 🔍 为什么会这样

UIA 是**"协作式"**的 —— 它需要**程序主动配合**：

| 技术 | 是否汇报控件清单 | UIA 表现 |
|---|---|---|
| **WPF**（微软做的界面） | ✅ 内置支持 | 清单完整，能读能点 |
| **WebView2**（内嵌浏览器） | ✅ 内置支持 | 内容能读 |
| **老式 Win32（NSIS）** | ❌ **不支持** | **只能靠系统兜底，信息残缺** |
| **自绘控件**（自己画的） | ❌ 通常不支持 | 读不到，或只有一个空壳 |

NSIS 属于第三类：它是**老式程序**，不做无障碍汇报，所以 UIA 只能通过系统兜底拿到极少信息 —— 表现就是"0 个控件 + 一堆空名窗口"。

> [!important] 核心认知（**这句话值得背下来**）
> **UIA 能读到什么，取决于程序愿不愿意告诉你，而不是取决于你有多努力。**
>
> 所以：**加重试、加超时、换更复杂的查询语句，全都不会有用。**
> **问题不在你的代码，在被测程序。**

---

## 🔧 解决：换到 Win32 层

Win32 是**更底层**的机制：不依赖程序汇报，直接枚举系统里的窗口对象。

| 能力 | 实测结果 |
|---|---|
| 列出顶层窗口 | ✅ 拿到「网易云音乐 安装」对话框 |
| 列出子控件 | ✅ 拿到按钮、输入框 |
| 读控件文字 | ✅ **能读**（但要清理一下，见下） |
| 点击控件 | ⚠️ **受限**（普通权限点不动管理员窗口，见 [[02-UIPI边界]]） |
| 读控件位置和尺寸 | ✅ 能读 |

**Win32 全通。** 所以项目里专门做了一套 Win32 的工具。

---

## ⚠️ 但 Win32 也有自己的 4 个坑

### 坑 1：会把"隐藏窗口"也列出来

Win32 列窗口时，**会把进程的隐藏消息窗也列出来**，比如：

- `Default IME`（输入法相关）
- `MSCTFIME UI`
- `.NET-BroadcastEventWindow`
- `Hidden Window`

**这些是程序内部用的，用户永远看不到。** 而 UIA 不会列它们。

> [!warning] 后果
> 如果不加**"只列可见窗口"**的过滤，这些隐藏窗口会被全当成「**未知弹窗**」→ 直接报失败。
>
> **类比**：你问"店里还有别人吗"，店员把**仓库里不出的货**也算上了 —— 你得自己加一句"只算在店里的"。

### 坑 2：读到的文字带着"小尾巴"

Win32 读到的按钮文字长这样：

```
关闭(&L)
取消(&C)
< 上一步(&P)
```

那个 `(&L)` 是**快捷键标记**（表示按 L 键也能触发）。

**必须把它剥掉**，才能和"关闭""取消"这样的白名单匹配上。

```
原始：  关闭(&L)
剥掉：  关闭      ← 这样才对得上
```

> [!tip] 记住这个坑的形状
> **跨层取数据时，要检查数据格式是否被加工过。**
> Win32 读到的不是"纯文字"，而是"带快捷键标记的原始文字"。

### 坑 3：自绘按钮**根本没有文字**

有些按钮是"画上去的"，读回来是**空的**。这时只能**按尺寸认**：

| 按钮 | 怎么认 |
|---|---|
| 立即安装 | 自绘无文字 → **按尺寸**（360×60） |
| 关闭叉 | 36×36 |
| 协议链接 | 最大的那个（144×25） |

> [!warning] 这是**最后手段**，不是优雅方案
> 它依赖"**尺寸永远不变**"，界面一改版就废。
> 而且**代码不可读** —— 别人看到 `21600` 不知道是什么。
> 方案承认这是脆弱点，并配了 OCR 作为确认补充。

### 坑 4：截图要用特殊方式

厂商向导是**分层窗口**（一种特殊的窗口渲染方式），常规截图**只能得到纯白**：

| 截图方式 | 结果 |
|---|---|
| 常规方式 | ❌ 纯白，什么都没有 |
| **特殊参数（`PW_RENDERFULLCONTENT`）** | ✅ 有内容 |

> [!tip] 这条"现在用不上"的结论为什么也记着
> 方案原文：*「走 Win32 前的兜底，现用不上但结论留着。」*
> **探明的技术结论即使当前用不上，也要记录** —— 下次遇到同类窗口不用重新试一遍。

## 🧠 记忆卡（考前背这一页）

### 口诀 ①：**菜单 vs 翻厨房**

> **UIA = 问服务员要菜单**（对方不给就没办法）
> **Win32 = 自己进厨房翻**（不依赖对方配合）

### 口诀 ②：**"瞎"的责任在对方**

> UIA 读到什么，**取决于程序愿不愿意说**。
> 读不到 = **对方不说**，不是你没使劲。
> → **所以加重试、加超时全都没用。**

### 口诀 ③：**趴窗户要加"只看店里"**

> Win32 会把**仓库里的货**也算上（隐藏窗口）。
> 得自己加过滤：**只算用户看得见的**。

### 口诀 ④：**小尾巴要剪掉**

> 读到的 `关闭(&L)` 带着快捷键标记。
> **剪掉 `(&L)` 才是"关闭"。**

### 四句串起来

```
① 菜单不给 → 换翻厨房（UIA 不行换 Win32）
② 责任在对方 → 别死磕 UIA
③ 仓库混进来 → 加可见性过滤
④ 带着小尾巴 → 记得剥快捷键标记
```

## 🎤 应对提问

> [!question]- Q1：UIA 读不到安装向导的控件，是 UIA 的 bug 吗？
> **不是。** UIA 是"协作式"协议：**程序实现接口，UIA 才有信息可读**。
> NSIS 不实现，所以 UIA 只能退到系统兜底，拿到残缺信息。
> **这是设计使然，不是缺陷。** 理解这点，就不会浪费时间在"怎么让 UIA 读到 NSIS"上。

> [!question]- Q2：为什么换了 Win32 就全通了？
> 因为 **Win32 不依赖程序配合** —— 它直接问**操作系统**"这台机器上有哪些窗口对象"。
> 而窗口对象是系统层面的存在，**不管程序愿不愿意汇报，它都在那儿**。
>
> **类比**：店员不给菜单，但**厨房里的锅碗瓢盆是客观存在的**，你进去翻就能找到。

> [!question]- Q3：为什么 Win32 需要自己过滤隐藏窗口，UIA 不用？
> 因为两者**枚举的层次不同**：
> - **UIA** 列的是"用户可见的界面元素"
> - **Win32** 列的是"**所有**顶层窗口"，包括只用于内部通信的隐藏窗口
>
> **规律：换到更底层的 API 时，"过滤责任"从框架转移到了调用方。**

> [!question]- Q4：`关闭(&L)` 直接和白名单里的"关闭"比，会怎样？
> **永远匹配不上** → 自动关闭弹窗的功能失效 → 首次启动的向导卡住。
>
> 这个坑很隐蔽：**你看代码觉得"明明比对了关闭按钮"，实际因为多了 `(&L)` 三个字符而失败。**

> [!question]- Q5："按尺寸认按钮"为什么是脆弱方案？
> 三个原因：
> ① 依赖**尺寸永远不变** —— 产品改版、缩放、换皮肤就废
> ② **代码不可读** —— 看到 `21600` 不知道是什么
> ③ **静默失败** —— 点错了不一定报错
>
> 所以它是**最后手段**，并配 OCR 做确认。

> [!question]- Q6：如果换一个厂商的安装器（不再是 NSIS），这套 Win32 通道还能用吗？
> ⚠️ **推断**：大概率能用，但**具体细节要重新探**：
> - 窗口类名还是那个标准对话框类吗？
> - 按钮有文字吗，还是自绘？
> - 静默参数是什么？
>
> 所以项目里有专门的**探针工具** —— **换安装器就重跑探针**。
> **架构上：Win32 通道是通用的，但控件细节必须重新探测。**
