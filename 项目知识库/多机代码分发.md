# 多机代码分发（共享盘裸仓库）

## 一句话

新测试机从**共享盘的裸仓库** `git clone` 拿代码 ——
**不需要外网、不需要 GitHub 令牌、不需要手工排除任何文件**。

## 共享盘现状（已搭好）

```
C:\hall-packages\repo\
  hall-auto.git                    裸仓库（HEAD -> refs/heads/main）
  Git-2.55.0.5-64-bit.exe          65343712 字节，钉住版本
  install_git.ps1                  6411 字节，UTF-8 with BOM
```

对外的 UNC 路径：`\\LAPTOP-VS5F7HF4\hall-packages\repo\`

- **钉住的 Git 版本**：`2.55.0.5`（官方 release 资产 `Git-2.55.0.5-64-bit.exe`）
- **SHA-256**：`D065A4E23C3D9A6B5073D609B5BE0830227EC3CA053C083BA385061DDFAF94C6`
  （取自官方 release 说明 `github.com/git-for-windows/git/releases/tag/v2.55.0.windows.5`，
  本机下载后已实测校验通过）
- 钉版本的理由同 7-Zip 夹具：**无外网机器只能靠共享盘这一份，必须可复现、可校验**。

## 为什么放在 `hall-packages` 里

- `hall-packages` 对节点是 **READ-only** —— 节点只需要 `clone` / `pull`（读），权限刚好对得上。
  节点**不该** push 代码，只读共享正好把这件事从"靠自觉"变成"靠权限"。
- **不用再提权**。建新共享要重跑 `tools\provision_share.ps1`（唯一的提权动作，交接里写明"已用完"）。
- 本机是共享宿主，push 走**本地路径** `C:/hall-packages/repo/hall-auto.git`，不受 SMB 只读限制。

## 新测试机操作（替换手册步骤 1）

**前提：先认证共享盘。** 共享的 NTFS 只授权 `hallshare`，**新机器默认连不上** ——
不先 `net use`，下面 ① ② 都会报「找不到网络路径」/「拒绝访问」，而报错看着像网络坏了。

```powershell
# ⓪ 先连共享盘（普通窗口即可，/persistent:yes 重启后自动重连）
net use \\LAPTOP-VS5F7HF4\hall-packages /user:hallshare "<共享盘密码>" /persistent:yes
dir \\LAPTOP-VS5F7HF4\hall-packages\repo        # 能看到 hall-auto.git / install_git.ps1 才算过

# ① 装 Git（一行，零依赖，无外网可用）
& "\\LAPTOP-VS5F7HF4\hall-packages\repo\install_git.ps1"

# ② 放行共享盘上的裸仓库（Git 把 UNC 当"非本地目录"，不放行 clone 直接失败）
git config --global --add safe.directory '\\LAPTOP-VS5F7HF4\hall-packages\repo\hall-auto.git'

# ③ 拉代码（走局域网；**必须显式给目标目录名**，否则落地成 hall-auto）
cd C:\Users\你的用户名\Desktop
git clone "\\LAPTOP-VS5F7HF4\hall-packages\repo\hall-auto.git" Huashuo-Dating-Automation
cd Huashuo-Dating-Automation

# ④ 之后照旧跑 bootstrap（管理员窗口）
```

> ⚠️ **装完 Git 要新开一个 PowerShell 窗口** —— 安装程序改了系统 PATH，但**当前窗口不会自动刷新**。
> `install_git.ps1` 最后会提醒这一句。
>
> UNC 路径如果 Git 不认，先映射盘符再 clone（**别忘了末尾的目标目录名**）：
> `net use Z: "\\LAPTOP-VS5F7HF4\hall-packages"` → `git clone Z:\repo\hall-auto.git Huashuo-Dating-Automation`。
> 节点侧本来就在用 `//LAPTOP-VS5F7HF4/hall-packages`（见 `hall_auto/fetch.py`），网络通路是现成的。

## `install_git.ps1` 为什么存在（引导悖论）

bootstrap 要先有代码才能跑，而按本方案拿代码要先有 Git —— 死锁。
所以装 Git **不能只做在 bootstrap 里**，必须有一个**不依赖仓库、不依赖 Python、不依赖外网**的入口。
它就是那个入口：只用系统自带 PowerShell（5.1 兼容），从同目录取安装包静默装。

行为：

| 情况 | 结果 |
| --- | --- |
| `Get-Command git` 能找到 | 打印版本，跳过（rc=0）。要重装加 `-Force` |
| `git` 不在 PATH，但 `C:\Program Files\Git\cmd\git.exe` 在 | 提示"新开窗口再试"，跳过（rc=0）—— 避免白装一遍 |
| 找不到安装包 | rc=2，提示确认共享盘连通性 |
| SHA-256 对不上 | rc=3，**拒绝执行** |
| 安装程序起不来 / 非 0 退出 | rc=4 |
| 退出码 0 但 `git.exe` 不在预期位置 | rc=5 |

实现上两个刻意选择：

1. **先拷到 `%TEMP%` 再装**。`Start-Process` 的 UNC 路径有坑（工作目录不能是 UNC），
   而且从网络位置跑安装程序还会撞 SmartScreen / 执行策略。拷一次，麻烦全没。
2. **不写 `/COMPONENTS`**。默认组件已含「Git from the command line and also from 3rd-party
   software」（即写进 PATH），正是我们要的。少写一个开关就少一个踩坑点。

> **源文件在仓库 `tools/install_git.ps1`，共享盘那份是拷贝。**
> 改完必须重新拷过去，否则一线拿到的是旧版：
> `Copy-Item tools\install_git.ps1 C:\hall-packages\repo\ -Force`
> 拷完确认 BOM 还在（PS 5.1 会把无 BOM 的 UTF-8 当 ANSI 读，中文报错变乱码）。

## 口径（必须定死，否则两边分叉）

- **只有本机能 push。** 本机同时推 `origin`（GitHub）和 `share`（共享盘）。
- **测试机只读不 push。** 由 `hall-packages` 的 READ-only 权限兜底。
- **共享盘裸仓库不是备份。** GitHub 仍是异地副本。但本机 `git fetch origin` 拿不到
  `origin/main` 远端跟踪引用（环境层，见《会话交接.md》）—— 所以**别用 `git status` 判断同步状态，
  权威口径是 `git ls-remote origin`**。

### 第二坑：pack 拷贝 `Permission denied` —— **共享盘 ACL 缺 `hallshare`**（2026-09-21，已定位并修复）

`safe.directory` 生效后 clone 往下走了一步：

```
Cloning into 'Huashuo-Dating-Automation'...
fatal: failed to copy file to 'Huashuo-Dating-Automation/.git/objects/pack/pack-309290e2….idx': Permission denied
```

#### 根因（一句话）

**共享盘上那 3 个 pack 文件的权限里没有 `hallshare`。**
`objects\pack\pack-*.{idx,pack,rev}` 的 DACL 只剩 `Administrators / SYSTEM / admin:(F)`
（从本地目录一起带过来的，见文末"为什么会这样"）。
节点以 `hallshare` 连过来 → **`HEAD`、`refs/`、松散对象全读得到，唯独 pack 读不到** →
git 卡在第一个 pack 文件上，报出那句指向桌面的 `Permission denied`。

#### 证据链（每一条都是实测，不是推断）

| 环节 | 事实 |
| --- | --- |
| **节点侧** | `Copy-Item <那个 .idx> $env:TEMP\probe.idx` → **"对路径…的访问被拒绝"** —— 直接证明是**读共享盘被拒**，与 git、与桌面都无关 |
| **宿主侧** | `icacls <那个 .idx>` → `Administrators/SYSTEM/admin:(F)`，**无 hallshare**；对照 `HEAD` / `refs/heads/main` → 有 `hallshare:(I)(R)`。**同一棵树下两种 ACL，这就是差异点** |
| **全盘审计** | `C:\hall-packages` 共 80 个文件，**只有这 3 个**缺 `hallshare`（其余含 `wheelhouse\`、两个安装包、安全工具都在） |
| **修复后** | `icacls "…\objects\pack" /reset /T /C` → 三个文件恢复 `hallshare:(I)(R)`；全盘复扫 **缺 0 个** |

#### 修法

在**共享宿主**上跑（让子项重新继承父目录权限 —— 父目录上本来就有 `hallshare` 授权）：

```powershell
icacls "C:\hall-packages\repo" /reset /T /C
```

⚠️ **千万别对 `C:\hall-packages` 本身跑 `/reset`** —— 那会把根目录上那条**显式的**
`hallshare:(OI)(CI)(R)` 一并抹掉（变成继承 `C:\` 的权限），节点从此整个共享盘都进不去。

#### 防复发：`tools/check_share_acl.ps1`

新增宿主侧自检脚本（退出码 0 = 全部可读 / 1 = 有文件缺 ACE 并列出明细与修法 / 2 = 路径不存在）。
**发新机之前必须跑，必须看到「读不到的：0」。** 已写进《交付前验收.md》的清单。
负路径实测能红（把账号名换成不存在的 `nosuchacct_zzz` → 80 个文件全被列出、rc=1）。

#### 为什么会这样（建裸仓库的方式埋的雷）

裸仓库是用 **`git clone --bare`** 建的，它**默认走硬链接**（`ls -l` 显示 pack 文件链接数为 4）——
pack 文件与本地仓库**共用同一个 inode**，于是**ACL 也跟着是本地那套**
（`C:\Users\admin\...` 那一支只有 `Administrators / SYSTEM / admin`，没有 `hallshare`）。

→ 以后建新裸仓库：用 **`git clone --bare --no-hardlinks`**，或建完立刻 `repack -ad`，
**然后跑一遍 `check_share_acl.ps1`**。

#### 这句话为什么误导（读 git 2.55 源码得到的，别再靠猜）

UNC 被 git 当**本地路径** → 走 `clone_local()` → `copy_or_link_directory()`，
它**不用传输协议**，而是**逐个文件把 `objects/` 拷过去**：

```c
unlink(dest);                                    // 先删目标；失败且非 ENOENT 会另报 "failed to unlink"
if (!link(src, dest)) { …sanity check…; continue; }   // 先试硬链接；跨盘必失败
option_no_hardlinks = 1;                              // 静默降级成"全部拷贝"
if (copy_file_with_time(dest, src, 0666))
        die_errno(_("failed to copy file to '%s'"), dest);   // ← 报的是 dest
```

`copy_file_with_time` 有**四条**路返回非 0，**全都打印同一句、且路径永远写目标**：

| # | 失败点 | 实际含义 |
| --- | --- | --- |
| 1 | `open(src, O_RDONLY)` | **读不了共享盘上的源文件** |
| 2 | `open(dst, O_WRONLY\|O_CREAT\|O_EXCL)` | 目标目录不许新建文件 |
| 3 | `copy_times` 里 `stat(src)` | 读不了源文件属性 |
| 4 | `copy_times` 里 `utime(dst)` | **字节已拷完**，只是改目标时间戳被拒 |

**所以"Permission denied 指向桌面那个文件"≠"桌面不让写"** —— 它可能是读共享盘被拒。
这是本项目第五次踩「报错指向错误的方向」。

#### 已经排除的（别再查）

| 怀疑 | 依据 | 结论 |
| --- | --- | --- |
| 共享盘仓库坏了 | `fsck` / `count-objects -v` | ✅ 干净；662 objects / 1 pack，报错里那个 pack 哈希就是共享盘上那一个 |
| `hallshare` 没有读权限 | `icacls` 三层 | ✅ `hallshare:(I)(OI)(CI)(R)`，继承来的 |
| **上次失败的残留只读文件** | 代码：`unlink(dest)` 在拷贝前跑，且目标用 **`O_EXCL`** | ❌ **不成立** —— 目标当时必然不存在，否则报的会是 "failed to unlink" 或 "File exists" |
| 桌面整体不让写 | 代码执行顺序：报错前 `init_db` 已在桌面建出 `.git/config`、`.git/HEAD`、`.git/hooks/*.sample`、`objects/`、`objects/pack/` | ⚠️ **基本不成立** —— 桌面明明能新建文件，"受控文件夹访问"这类全局拦截说不通 |
| 源侧不通 | 本机从 UNC clone 到临时目录（`-c safe.directory=…` 一次性写法 / `--no-local`） | ✅ 都通，拿到 `f5059de` |

**真因落在第 1 条路：读源被拒** —— 节点侧 `Copy-Item` 实测直接复现，与桌面、杀软、磁盘空间都无关。

#### 以后遇到同类报错的分诊顺序（一条命令）

```powershell
Copy-Item "<共享盘上那个文件>" $env:TEMP\probe.bin -Force
```

- **拷得出来** → 读源没问题 → 查目标侧（`Get-MpPreference | Select-Object EnableControlledFolderAccess`、
  `Get-PSDrive C | Select-Object Used,Free`）。
- **拷不出来 / 访问被拒** → **共享盘 ACL 问题**：在宿主上跑 `tools\check_share_acl.ps1`，
  **别在测试机上瞎折腾**。

#### 顺带：`--no-local` 的两个副作用（本机实测）

```powershell
git clone --no-local "\\LAPTOP-VS5F7HF4\hall-packages\repo\hall-auto.git" Huashuo-Dating-Automation
```

- **免掉 `safe.directory`** —— 本机 global 配置为空时，普通 clone 报 dubious ownership，
  `--no-local` 直接成功（ownership 检查在 `copy_or_link_directory()` 里，而它不走那条路）。
- 换掉"逐文件拷贝"这条路（改走传输协议），**顺带绕开这类 ACL 差异导致的拷贝失败**。
  ⚠️ 但**它不是这次的修法** —— 真因在共享盘 ACL，已修；`--no-local` 只算多一条退路。

⚠️ ① 只解决"逐文件拷贝"这条路。**如果真因是"目标不许新建文件"，`--no-local` 一样会失败**
（它照样往 `objects/pack/` 写 pack）。**所以先跑上面那条一句话分诊，别直接上绕法。**

⚠️ **定位出来之前别写进两份对外文档** —— 先把测试机的分诊结果收回来。

**沙箱验收查出的真缺陷（已修）**

- `$DefaultGitExe` 原来用 `${env:ProgramFiles}` 拼路径。**该环境变量在某些受限会话里是空的**，
  于是 `Join-Path` 抛「无法将参数绑定到参数"Path"，因为该参数是空值」——
  完全看不出根因，而且发生在**做任何事之前**（脚本第一行就死）。
  **修**：改用 `[Environment]::GetFolderPath([Environment+SpecialFolder]::ProgramFiles)`。
  这个缺陷只会在"环境变量不全"的会话里出现 —— **正是本机跑不出来的那一类**。

**未验（下次别重查，也别当已验）**

  真跑一遍安装会在这台机器上**装一份 Git for Windows**（本机 git 是 `/mingw64/bin/git`
  工具链自带可移植版，`C:\Program Files\Git` 不存在），所以没跑。
  → 第一台真测试机上线时**盯着这一步**，跑完把结果补记回本节。
- ⚠️ **`Get-Command git` 命中的那条分支未单独触发** —— 本机 PowerShell 会话里改了 PATH 之后
  `Get-Command git` 仍查不到（会话限制：同一路径 `Test-Path` 是 True）。
  逻辑只有 3 行、且相邻的"PATH 没刷新"分支已实测，风险低 —— **但没验就是没验**。
- ✅ **UNC 路径 clone 已在真 SMB 客户端上验过（2026-09-21 15:18 / 15:30，测试机报回）** ——
  测试机照**旧版**文档走，**原样复现**上面那两个错误（dubious ownership + `cd` 路径不存在）；
  按文档补上 `safe.directory` 后**这一关过了**，紧接着撞上「第二坑」的 pack 拷贝 `Permission denied`。
  **两关都在真客户端上出现过，不是本机独有现象。**
- ✅ **`--no-local` 能免掉 `safe.directory`**（2026-09-21 15:34，本机实测）——
  本机 global 配置里**没有** `safe.directory`：普通 `git clone <UNC>` 报 dubious ownership；
  **同一条件下** `git clone --no-local <UNC> <dest>` **直接成功**（拿到 `f5059de`）。
  原因：ownership 检查在 `copy_or_link_directory()` 里，而 `--no-local` 根本不走
  `clone_local()`，改走传输协议 —— **绕开那条路就绕开了这个检查**。
- ✅ **`-c safe.directory=…` 一次性写法可用**（同上实测）—— 不必动全局配置：
  `git -c safe.directory='\\…\hall-auto.git' clone <UNC> <dest>`。
- ⚠️ **但 `--no-local` 没在测试机上验过**，而且它**只换掉"逐文件拷贝"这一条路**，
  不解决「第二坑」里的其他可能（见上一节）。
