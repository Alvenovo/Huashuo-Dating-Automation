# 交付前验收：手册能不能被照做

> 最后更新：2026-09-21
> 状态：已确认（本轮实跑得出）
> 触发：改完 `tools/` / `hall_auto/` / 《测试机操作手册.md》之后，**发出去给测试同事之前**

## 为什么需要这一份

2026-09-17 → 09-21 期间，同一件事被复核了三轮，**每轮都能查出真缺陷**（3 → 7 → 3 处）。
根因不是代码质量，是**验收方法**：

| 方法 | 结果 |
| --- | --- |
| 读代码、对命令名 / 步骤名 / 参数个数 | ❌ 对得上但跑不通。三轮里第一轮就是只做了这个 |
| 在本机按手册跑一遍 | ❌ 本机是"跑了两年的老机器"，`installer_dir` 躺着 7 个旧包、`config.local.yaml` 是配好的 —— **本机有什么，正好把新机上的坑全盖住** |
| **用临时目录模拟新机初始状态，跑真实代码** | ✅ 三轮里唯一能挖出硬阻断的方法 |

**核心判据：本机跑得过 ≠ 新机跑得过。** 只要验证用的是"本机现状"，就一定漏掉新机上的坑。

## 新机的初始状态长什么样（模拟时必须照这个摆）

| 维度 | 新机 | 本机（会骗人的那个） |
| --- | --- | --- |
| `config.local.yaml` | **不存在** → 读到 `config.yaml` 的占位路径 `C:/Users/ASUS/...` | 存在，且是配好的真实路径 |
| `installer_dir` | **空目录** | 躺着 7 个历史安装包 |
| `_cache/` | 空 | 有 |
| 环境变量 | 空（管理员窗口尤其） | 常驻着 `HALL_FARM_ROOT` 等 |
| 共享盘 | 未认证 | `/persistent:yes` 挂着 |
| 计划任务 `HallAutoP1` | 不存在 | 已建 |
| **`.venv`** | **不存在** | 存在且依赖齐全 |
| **系统 Python 里的第三方包** | **一个都没有**（PyYAML 也没有） | 本机 `.venv` 有；而且你习惯用 `.venv\Scripts\python.exe` 跑，等于**永远看不到"系统 Python 缺包"这一层** |
| **外网** | 可能完全没有 | 通常有（所以"能装上"这件事本身不可信） |

## 怎么做（一次实跑，20 分钟）

写一个**临时审计脚本**（放 `%TEMP%`，不进仓库），用临时目录 + **import 真实代码**，把手册的每条承诺变成一条断言：

1. 列出要验的承诺：13 步顺序、每步的预期输出、失败分支的提示语、落盘字段、套件名单。
2. 用 `tempfile` 造新机：空 `config.yaml`（从仓库拷模板）、空 `installer_dir`、清掉相关环境变量。
3. 对**纯函数**（`step_write_local_config` / `_ensure_seven_zip_fixture` / `take_task` / `cmd_aggregate`）直接调，不整个跑 bootstrap（会真装 7-Zip、真建计划任务）。
4. 需要整条链路的（dispatch → agent → 回执 → 证据 → aggregate）用**本地目录**当农场根跑一次，套件挑 `unit`（不碰界面、1 分钟）。
5. 断言失败时**先怀疑自己的测试**，再怀疑代码 —— 本轮 3 个 FAIL 里有 1 个是我的测试包 sha 不对、1 个是我的正则写错。

### 三条"真跑一遍"的硬要求（2026-09-21 补，都是被真缺陷逼出来的）

上面 1-5 步验的是**函数级承诺**，验不出"整条链在裸机上根本起不来"。所以再加三条：

6. **用系统 Python 跑，不要用 `.venv\Scripts\python.exe`。**
   找一台**没有第三方包**的解释器（比如本机那个裸 Python 3.12 / 3.13），
   直接 `python -X utf8 tools\bootstrap_machine.py --help`。
   **只要它连 `--help` 都打不出来，新机就是白干** —— 这一条当场就查出过
   `ModuleNotFoundError: No module named 'yaml'`（`hall_auto/__init__.py` 急加载 `config`）。
7. **把 pip 源指到一个死地址，再跑一次依赖安装。**
   `PIP_INDEX_URL=http://127.0.0.1:9/simple` 就能模拟"完全没有外网"。
   跑完检查日志里出现的是**离线**安装（`--no-index --find-links`）还是在线 ——
   只看到"装成功了"不算数，本机有外网时在线装也会成功，那是假通过。
8. **断言不能只看"有没有报错"，要看"报的是不是那条路"。**
   例如 `step_venv` 在无网机器上必须打印「用离线 wheelhouse：…」；
   第 5/7/8/10 步**不许**出现「读配置失败」——出现就是静默跳过（假绿）。
9. **加了"守卫测试"（锁某条策略的用例）之后，必须故意制造一次违规，确认它真能红。**
   守卫用例只跑一遍绿，等于什么都没验 —— 它可能压根没匹配到任何文件
   （剪枝写错、后缀写错、正则漏了引号），却永远显示 passed。
   做法：临时塞一行违规 → 跑出红 → **确认报错里指出了"文件:行"** → 删掉；
   再把被测值改成"允许值"（如把 `config.yaml` 的 `installer_dir` 改成 `C:/Users/Public/...`）→ 也应能红。
   **能红的守卫才叫守卫；只会绿的守卫是安慰剂。**
   例：`tests/unit/test_repo_hygiene.py`（禁代码里硬编码机器路径）就是这么验过的。
10. **发新机之前跑 `tools\check_share_acl.ps1`，必须看到「读不到的：0」。**
    共享宿主自己就是管理员，**任何权限问题在本机都看不见** —— 这是「本机跑得过 ≠ 新机跑得过」
    最纯粹的一例，而且它比前九条更隐蔽：**报错指向完全错误的方向**。
    2026-09-21 实测：裸仓库那 3 个 pack 文件的 ACL 里没有 `hallshare`
    （裸仓库用 `git clone --bare` 建的，默认走硬链接，把本地目录的 ACL 一起带了过来），
    节点读不了 pack，git 报的却是
    `failed to copy file to '<桌面上的目标路径>': Permission denied` ——
    一线会去查桌面保护策略、杀软、磁盘空间，全错。
    负路径验法：把 `-Account` 换成不存在的账号（如 `nosuchacct_zzz`），
    脚本必须把全部文件列出来并 rc=1 —— **只会 rc=0 的检查等于没检查**。

**收尾铁律：断言不能留在临时脚本里。** 每条确认的缺陷都要变成一个常驻回归测试（本轮固化了 34 条），否则下一个人还会踩。

## 本轮用这个方法挖出来的 6 个真缺陷（都已是历史，留作模式参考）

| 模式 | 具体表现 | 为什么本机会盖住 |
| --- | --- | --- |
| **回执与汇总的数据没接通** | `aggregate` 报告的「凭据」列恒为 ✗（凭据只写在 `done/` 回执里，汇总只读 `results/`） | 本机从不跑多机汇总，`aggregate` 只被"列在不在"检查过 |
| **取包链少了共享盘那一段** | 离线新机上共享盘明明有钉住包，7-Zip 装不上、`reset_fixture` 报「包不存在」 | 本机 `installer_dir` 直路径就有那个包 |
| **落点与查找位置不一致** | 包取到 `_cache/fixtures/`，而 `update_package_path` 只认 `installer_dir/fixtures/` | 同上 |
| **自检名不副实** | bootstrap 第 12 步 `-m unit` 只跑 127/260 条，漏掉的全是多机链路模块 | 本机从没数过自检到底跑了几条 |
| **文档承诺 ≠ 代码行为** | 手册写 `login-manual`「永不进农场」，`dispatch` 照投（节点会卡在等输入） | 本机从没真投过它 |
| **证据错认** | 本轮没产出证据目录时，回传的是**上一轮的旧目录**（张冠李戴） | 本机每次都跑得出证据，这条分支进不去 |
| **自举链条断在第一行**（2026-09-21 第二轮） | 全新机器上 `bootstrap_machine.py` 在**打印第一行之前**就 `ModuleNotFoundError: No module named 'yaml'` —— 而"装依赖"正是它的第 2 步 | 本机 `.venv` 里 PyYAML 装好了，而且你习惯用 `.venv\Scripts\python.exe` 跑，**永远碰不到"系统 Python 没包"这一层** |
| **静默跳过导致假绿**（同上） | 系统 Python 上第 5/7/8/10 步各自 `from hall_auto.config import load_config` 抛 ImportError，被 try/except 吞成一行日志 → 全部跳过，最后照样打印"全部通过" | 本机用 `.venv` 跑，那几步真的执行了。**假绿只有"换错解释器"时才出现，而你不会主动去换** |

## 复核《测试机操作手册.md》时逐项要对的清单

- [ ] 13 步**顺序**（顺序错会让环境变量白设 —— 管理员窗口不继承 `$env:`）
- [ ] 每步**预期输出的字面串**（手册写 `[OK  ]` 而实际 `[OK]` 就会让人以为失败）
- [ ] 失败分支的**提示语**（手册引号里的话必须是代码里真有的串，否则一线 grep 不到）
- [ ] **落盘字段**（`farm_root` / `baseline_setup` / `security.tools_dir` 是否真写进 `config.local.yaml`）
- [ ] **套件名单**与 `hall_auto/suites.py::SUITES` 一致
- [ ] **前置条件清单覆盖了所有"新机上会缺"的项**（这一条最容易漏，因为它不在代码里，在现实里）
      —— 尤其：**pip 源 / 外网**（第 2 步要联网）、**磁盘空间**（盘满的报错长得像"共享盘坏了"）。
      判据：拿一台**真的裸机**过一遍清单，凡是清单没提、又确实会卡住的，就是漏项。
- [ ] **每条命令"在它所在的那一步"真的跑得起来** —— 最容易错的是解释器：
      `.venv\Scripts\python.exe` 要到 bootstrap 第 2 步才建出来，**排在 bootstrap 之前的步骤不许用它**。
      2026-09-22 清单第 3.5 步就是这么错的：探针命令用了 `.venv`，而 `.venv` 还不存在，
      全新机器上必报「系统找不到指定的路径」，一线会以为 Python 没装好。
      守卫：`test_sync_handbook.py::test_checklist_does_not_use_the_venv_before_bootstrap`。
- [ ] **Python 版本口径统一到 3.12** —— 离线 `wheelhouse` 是 `cp312` 的，
      凡"让人装 Python"的地方都必须写 3.12，不许写"3.x"（写了等于让人装最新版）。
      2026-09-22 清单第 1 步让人从 python.org 下"64 位安装包"（今天给的是 3.13/3.14），
      无外网新机会在**第 4 步第 2 步硬卡**，而同一份清单还声称"外网不是必需的"。
      守卫：`test_sync_handbook.py::test_both_docs_pin_python_312`。
- [ ] **桌面/分发副本同步了**：先设 `$env:HALL_SHARE_PASSWORD`，再跑 `tools/sync_handbook.py`
      （`--check` 能看出旧没旧，rc=1 就是旧了）。
      **手工拷的副本一定会漂，而且不会报错** —— 2026-09-21 真发生过：桌面那份还停在 09-18 的
      「10 步版」，仓库已经是「12 步版」，差了整整三轮修复（含 6 个硬阻断）。
      漏的代价是测试同事拿着旧手册，踩的正是已经修好的坑。
      ⚠️ **同步出去的是「发放版」** —— 真密码从环境变量**现场替换**进文档，仓库里永远只有占位符；
      **没设变量时脚本报错退出（rc=1），不会静默发一份密码写着 `<共享盘密码>` 的废文档**
      （那份发出去看着是好的，一线要到 `net use` 报 401 才发现）。
- [ ] **默认值**（新机 `installer_dir` 落哪、包占多少空间、闸门默认开还是关）

后六项已有常驻回归测试守着（`tests/unit/test_bootstrap_policy.py` 末尾两个 drift 用例 +
`test_farm_control_policy.py`；解释器顺序与 Python 版本这两条在 `tests/unit/test_sync_handbook.py`），
改代码/文档后跑 `tests/unit` 就会红。

## 手边没有 `HALL_SHARE_PASSWORD` 时，怎么更新桌面副本（2026-09-22 补）

**背景**：`sync_handbook.py` 靠环境变量**重新渲染**整份文档，所以没设变量它按设计 rc=1 拒绝干活
（见上面那条：不静默发占位版）。但**这不等于桌面那份就没法更新** —— 2026-09-22 我一开始就是
这么判的，用户当场反问「为什么不更新桌面上的新机操作清单啊，我就对照着这个在新机上操作的呀」。

**正道还是跑脚本**（能拿到密码就走它）。只有拿不到密码、而改动又**不碰任何凭据行**时，
才用下面的搬运法：

1. 把「仓库旧版 → 仓库新版」的**行级 diff** 算出来（`difflib.SequenceMatcher`，
   `git show <旧 commit>:<路径>` 拿旧版）。
2. 拿每个改动块去**桌面那份**里按内容定位，原地替换 / 插入。
   - 替换块：老块必须**唯一命中**，命中 0 次或多次都停手；
   - **插入块**（老块长度为 0）没法靠内容定位 —— 拿**后一个 equal 块的前 3 行**当锚
     （拿不到就用前一个 equal 块的末 3 行）。⚠️ 两个坑都踩过：v1 直接判"插入块 0 命中"停手；
     v2 想用 equal 块推进游标，但桌面副本在标题下多了一段「发放版」横幅，
     **第一段 equal 块**（仓库 1-22 行）在桌面里根本不存在。
3. **复核**（这一步不能省）：桌面侧改动的行集合必须与仓库侧**完全一致** —— 行数也要相等。
   只要动了别的行（把凭据行搅了、少搬一段）就报出来。
4. **终检**：桌面版与仓库版逐行对齐后，**所有**差异必须只落在
   ①含凭据占位符的行（把占位符位置换成 `.+` 做正则匹配，**不需要知道密码**）
   ②「发放版」横幅那 3 行。行数差 = 横幅 3 行 + 1 空行。

5. **最强复核：与渲染产物逐字节比**（2026-09-22 补）。桌面那份里就躺着真密码，现读出来喂给
   `render_release(源文档, 密码, 文件名)`，结果应当与桌面文件**逐字节相同** ——
   等于证明「搬出来的 = 跑脚本生成的」，比第 4 条逐行比对更硬。
   **只差末尾 `\r\n` 是最常见的一种**：搬运法把文件拆成行列表再 `join` 写回时容易丢掉末尾换行
   （2026-09-22 上一轮就是这么丢的，桌面版比脚本产物少 2 字节），而 `--check` 会一直说「旧了」、
   看不出原因。所以搬完补一句 `if not data.endswith(b"\r\n"): data += b"\r\n"`，再比一次。

**硬约束**：搬运法只对"不碰凭据行"的改动成立。改到了凭据行（新增占位符、改 `net use` 那几行）
就必须回去走脚本 —— 否则发放版里会留一个没人替换的占位符，而那份**看着是好的**。
搬完 `git status` 干净不代表桌面新了：**桌面那份不进 git，脚本和守卫都看不见它**。
