## 1. 装 Python

1. 打开 `https://www.python.org/downloads/windows/`
2. 下载 **64 位**安装包（Windows installer 64-bit）
3. 运行安装包，**第一屏最下面勾上 `Add Python to PATH`**，再点 `Install Now`
4. 装完**开一个新的 PowerShell 窗口**，敲：

   ```powershell
   python --version
   ```

**应该看到**：`Python 3.x.x`

**对不上就停**：
- 弹出微软商店 → 去 设置 → 应用 → 高级应用设置 → 应用执行别名，关掉 `python.exe` 和 `python3.exe`，回第 1 步重装
- 报 `not recognized` → 勾 PATH 那步漏了，回第 3 步重装

## 2. 先连共享盘，再把代码放到桌面

### 2.0 先连共享盘（**必做**）

共享盘要账号密码才能进，**新机器默认连不上**（NTFS 只授权了 `hallshare`，你本机账号在网络上是"别人"）。
不先连这一步，下面装 Git、拉代码会直接报「找不到网络路径」或「拒绝访问」——
看着像网络坏了，其实只是没认证。

在**普通**（不用管理员）PowerShell 里敲：

```powershell
net use \\LAPTOP-VS5F7HF4\hall-packages /user:hallshare "<共享盘密码>" /persistent:yes
```

**应该看到**：`命令成功完成。`

**马上验一次**：

```powershell
dir \\LAPTOP-VS5F7HF4\hall-packages\repo
```

**应该看到**：`hall-auto.git`、`Git-2.55.0.5-64-bit.exe`、`install_git.ps1`

**对不上就停**：

| 看到什么 | 什么意思 | 怎么办 |
| --- | --- | --- |
| 系统错误 53 / 找不到网络路径 | 网络或防火墙不通（445 被挡、不在同一局域网、机器名解析不了） | 先 `ping LAPTOP-VS5F7HF4`；通了再 `Test-NetConnection LAPTOP-VS5F7HF4 -Port 445`。是 `False` 就找组长放行 445 |
| 系统错误 67 / 找不到网络名 | 共享名写错，或包源机上共享没建 | 核对是 `hall-packages`；包源机上敲 `net share` 能看到它 |
| 系统错误 1326 / 登录失败 | 密码不对（`hallshare` 密码被重置过） | 找组长要当前密码 |
| 拒绝访问（错误 5） | 网络是通的，但用的**不是 `hallshare` 账号** | 本步命令没生效。**别在资源管理器里点进去输别的账号** —— 会留下错误连接，后面更难收拾 |
| 系统错误 1219 / 多重连接冲突 | 这台机器已经用别的账号连过包源机了（多半就是在资源管理器里点进去过） | 先 `net use * /delete /y`，再重跑本步 |

**三点说明**：

- **为什么要 `/persistent:yes`**：重启后自动重连，不用每次开机都敲。密码交给 Windows 凭据管理器（DPAPI 加密），**不是明文落盘**。
- **这一步只连 `hall-packages`**（放代码和依赖包那个）。任务中转站 `hall-farm` 由第 4 步的铺环境脚本自己连，第 7 步再手工验一次。
- 管理员窗口里如果报「拒绝访问」，就在**那个管理员窗口里**再跑一次本步命令。

### 2A · 从共享盘 clone（推荐）

**第 1 步：装 Git。** 一行命令，零依赖，无外网也能用：

```powershell
& "\\LAPTOP-VS5F7HF4\hall-packages\repo\install_git.ps1"
```

**应该看到**（结尾三行）：

```
[git-setup] 完成：git version 2.55.0.5.windows.5
[git-setup] 当前窗口还没刷新 PATH，先这样用：& "C:\Program Files\Git\cmd\git.exe" --version
[git-setup] **新开一个 PowerShell 窗口**，git 才直接在 PATH 上。
```

⚠️ **装完必须新开一个 PowerShell 窗口。** 安装程序改了 PATH，但当前窗口不会自动刷新 ——
不新开的话下一步会报「git 不是内部或外部命令」。

**第 2 步：放行共享盘上的裸仓库。**

Git 把 `\\机器名\...` 这种 UNC 路径当成"非本地目录"，**不放行就不给 clone**：

```powershell
git config --global --add safe.directory '\\LAPTOP-VS5F7HF4\hall-packages\repo\hall-auto.git'
```

**没有输出就是成功。** 只做一次，以后 `git pull` 也受用。

**第 3 步：拉代码。**

```powershell
cd C:\Users\你的用户名\Desktop
git clone "\\LAPTOP-VS5F7HF4\hall-packages\repo\hall-auto.git" Huashuo-Dating-Automation
cd Huashuo-Dating-Automation
```

⚠️ **末尾那个 `Huashuo-Dating-Automation` 不能省。** 不给它，git 按仓库名落地成 `hall-auto`，
后面所有 `cd Huashuo-Dating-Automation` 全部报"路径不存在"。

**应该看到**：`Cloning into 'Huashuo-Dating-Automation'...`，然后文件数跑到 100%。

**对不上就停**：

| 看到什么 | 怎么办 |
| --- | --- |
| `fatal: detected dubious ownership in repository at '\\...'` | **第 2 步没做**（Git 不放行 UNC 路径）。照报错里给的那行 `git config --global --add safe.directory '...'` 跑一遍，再重试 |
| `fatal: failed to copy file to '…\.git\objects\pack\…idx': Permission denied` | **共享盘权限缺 `hallshare`，不是你这台机器的问题。** 报错指向桌面上的文件，但真因在共享盘那一侧 —— **你在本机怎么折腾都没用**。把整段报错发给负责人，让他在共享宿主上跑 `tools\check_share_acl.ps1`，看到「读不到的：0」之后再重试 |
| `cd : 找不到路径 ...Huashuo-Dating-Automation` | clone 漏了目标目录名，落地成了 `hall-auto`。删掉它，回第 3 步带上 `Huashuo-Dating-Automation` 重跑 |
| `git 不是内部或外部命令` | 装完 Git 没新开窗口。关掉重开一个 PowerShell，回第 2 步 |
| `找不到网络路径` / 系统错误 53 / 拒绝访问 | 共享盘没连上 / 没认证。回第 2.0 步 |
| `fatal: repository ... does not exist` | 共享盘没连上，或共享名写错。回第 2.0 步。实在不行映射盘符兜底（origin 会记成 `Z:\...`，跨会话会失效，只临时用） |
| 脚本报「找不到安装包」 | 共享盘没连上，回第 2.0 步 |
| 脚本报「校验失败，拒绝执行」 | 安装包坏了。找组长重新放一份到 `\\LAPTOP-VS5F7HF4\hall-packages\repo\` |

### 2B · 兜底：不下 Git（**只在共享盘连不上、但这台机器能上外网时用**）

**先试 B-1。能打开浏览器就用它，连令牌都不用申请。**

#### B-1 · 浏览器下载（不用令牌，最省事）

1. 在这台测试机的浏览器里打开：

   ```
   https://github.com/Alvenovo/Huashuo-Dating-Automation
   ```

2. 没登录就先用**有仓库权限的账号**登录。看不到仓库 = 账号没被拉进来，回第 0 步
3. 点页面右上方的绿色 **`Code`** 按钮 → 弹出框最下面点 **`Download ZIP`**
4. 浏览器会下载一个 `Huashuo-Dating-Automation-main.zip`
5. 右键 → 全部解压缩，解压出来一个文件夹 `Huashuo-Dating-Automation-main`
6. **把文件夹改名，去掉后面的 `-main`** → `Huashuo-Dating-Automation`
7. 把它放到 `C:\Users\你的用户名\Desktop\`

**应该看到**：`C:\Users\你的用户名\Desktop\Huashuo-Dating-Automation\`

#### B-2 · 命令行下载（要一个令牌）

**只在 B-1 走不通时用**（比如这台机器不能上浏览器）。

**第 1 步：申请令牌。** 令牌就是一串代替密码的长字符串 —— GitHub 已经不允许用账号密码下载私有仓库了。
**只做一次，约 5 分钟。**

1. 用**有仓库权限的账号**登录 GitHub
2. 打开这个链接（名称和权限已经预填好了，直接改你要的就行）：

   ```
   https://github.com/settings/personal-access-tokens/new?name=hall-auto-download&description=read-only+repo+download&contents=read
   ```

   打不开就手动走一遍：右上角头像 → **Settings** → 左侧最下面 **Developer settings**
   → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**

3. **Expiration**：选 90 天（或按团队规定）
4. **Repository access**：选 **Only select repositories** → 下拉里勾上 **Huashuo-Dating-Automation**
5. **Permissions** → 展开 **Repository permissions** → 找到 **Contents** → 选 **Read-only**
   - **只要这一个权限就够了**，别多给
   - 页面上其他权限全部留 **No access**
6. 拉到底，点 **`Generate token`**
7. 页面顶部出现一串以 **`github_pat_`** 开头的字符串 —— **这就是令牌，只显示这一次，立刻复制走**

**第 2 步：用它下载。** 打开 PowerShell，一行行敲：

```powershell
$ProgressPreference = "SilentlyContinue"
[Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12
cd C:\Users\你的用户名\Desktop

$tok = Read-Host "粘贴令牌"          # 粘贴后回车，屏幕上不会显示

Invoke-WebRequest -Headers @{ Authorization = "Bearer $tok" } `
  -Uri "https://api.github.com/repos/Alvenovo/Huashuo-Dating-Automation/zipball/main" `
  -OutFile repo.zip -MaximumRedirection 5

Expand-Archive repo.zip -DestinationPath _tmp_repo
$inner = Get-ChildItem _tmp_repo | Select-Object -First 1
Move-Item $inner.FullName Huashuo-Dating-Automation
Remove-Item _tmp_repo -Recurse -Force
Remove-Item repo.zip -Force

# 清理：别把令牌留在窗口变量和命令历史里
Remove-Variable tok
Clear-History
Remove-Item (Get-PSReadlineOption).HistorySavePath -ErrorAction SilentlyContinue
```

**应该看到**：`C:\Users\你的用户名\Desktop\Huashuo-Dating-Automation\`

**报错对照**：

| 报错 | 什么原因 | 怎么办 |
| --- | --- | --- |
| `401 Unauthorized` | 令牌复制不完整，或粘贴时带了空格/换行 | 重新生成一个，`Read-Host` 那里粘贴后**别再敲空格** |
| `404 Not Found` | **权限不够时 GitHub 会假装"仓库不存在"** | 回第 2 步第 4 项，确认勾上了 `Huashuo-Dating-Automation` |
| `403 Forbidden` | 令牌过期，或 **Contents 不是 Read-only** | 回第 2 步第 5 项检查；或重新生成 |
| 卡住不动 / 重定向出错 | PowerShell 跟重定向出问题 | 改用下面这行（`curl.exe` 是系统自带的） |

```powershell
curl.exe -L -H "Authorization: Bearer $tok" -o repo.zip "https://api.github.com/repos/Alvenovo/Huashuo-Dating-Automation/zipball/main"
```

⚠️ **令牌不能写进任何文件、不能贴进聊天或群里。** 上面最后三行就是清理命令，别省。

## 4. 跑铺环境脚本

**在同一个管理员窗口里**，接着敲：

```powershell
cd C:\Users\你的用户名\Desktop\Huashuo-Dating-Automation
powershell -NoProfile -ExecutionPolicy Bypass -File tools\bootstrap_machine.ps1
```

两个可选参数：

```powershell
# 节点名要用 R01 这种编号时（必须和控制机 dispatch --nodes 里写的完全一致）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\bootstrap_machine.ps1 -NodeId R01

# 系统盘空间紧张时，指到别的盘
powershell -NoProfile -ExecutionPolicy Bypass -File tools\bootstrap_machine.ps1 -InstallerDir "D:\Test\大厅"

# wheelhouse 没放在仓库目录下、也没放共享盘时，手动指路
powershell -NoProfile -ExecutionPolicy Bypass -File tools\bootstrap_machine.ps1 -Wheelhouse "D:\wheelhouse"
```

**耗时 5-15 分钟，中途别关窗口。**

⚠️ **它会打印两遍「机器铺设」，这是正常的。**
第一遍只建虚拟环境 + 装依赖，然后自动换成虚拟环境的解释器把整套重跑一遍。
第二遍开头会有一句「依赖已就绪。换用 venv 的解释器重跑整套」。
**看到这句就对了，不是重复执行。**

**应该看到**（结尾长这样）：

```
[OK] 环境自检
[OK] 虚拟环境与依赖
...
[OK] 提权计划任务
[OK] 自检 tests/unit
结果：全部通过，本机已可跑批
```

无外网的机器，第 2 步应该长这样 —— **关键是看到「离线」两个字**：

```
[OK] 虚拟环境与依赖
    用离线 wheelhouse：\\LAPTOP-VS5F7HF4\hall-packages\wheelhouse（Python 3.12，12 个 wheel）
    离线装依赖：requirements.txt（--no-index --find-links）
    依赖安装完成，已记录标记 .deps_ok
```

**对不上就停**，把屏幕上的输出整段留好。

脚本最后会打印一个报告路径：`reports\bootstrap\bootstrap_<机器名>_<时间>.json`

**报错对照**：

| 看到什么 | 怎么办 |
| --- | --- |
| `[FAIL] 虚拟环境与依赖` + 「探不到 pip 源」 | 这台机器没外网、又没找到 `wheelhouse\`。**共享盘 `hall-packages\wheelhouse\` 上已经备好一份（Python 3.12）** —— 先确认共享盘连上了（`net use`）；Python 版本对不上就让组长用对应版本重跑一次 `fetch_wheelhouse.py` |
| 「wheel 是给 Python 3.12 下的，本机是 3.13」 | 你的 Python 版本和打包那台不一致。要么把你的 Python 换成 3.12，要么找组长要一份对应你版本的 `wheelhouse` |
| 「requirements.txt 改过了」 | 那份 `wheelhouse` 是旧的。找组长在有网机器上重跑一次 `fetch_wheelhouse.py` |
| 脚本在第 2 步 FAIL 之后就停了，后面步骤一条没跑 | **故意停的**。依赖没装好，后面每一步都会报假错，所以直接停。修好依赖后**重跑同一条命令**即可（做过的会跳过） |
| 第 12 步 `[FAIL] 自检 tests/unit`，下面列了几条 `FAILED tests/unit/…` | 脚本**已经自动换进程重跑过这几条**，还 FAIL 就是重跑也红。看日志 `reports\bootstrap\selftest_*.log`（重跑那轮追加在末尾，以 `[重跑]` 开头）里的断言原文；单跑一条：`.venv\Scripts\python.exe -m pytest <上面那条> -q`。若红的正是"共享盘拷贝"那几条、报 `[Errno 22] Invalid argument`，那是**本机杀软把刚写的临时文件判毒**，属已知环境问题（《运行手册》坑 6），不是代码坏了 |
| 输出里「机器铺设」出现了**两遍** | **正常**。第一遍建虚拟环境 + 装依赖，第二遍换解释器跑完整 12 步 |

## 接下来跑批

⚠️ **下面三条是同一个脚本的三个模式，不是三个任务。挑一条敲，别连着敲。**
按你现在要干的事对号入座：

| 你现在要干的事 | 敲哪条 |
| --- | --- |
| 刚铺完环境，先验一下这台机器能不能取到任务 | **① `--once`** |
| 正式跑批，等控制机投任务过来 | **② `--loop`** |
| 本机调某个套件，不走共享盘 | **③ `--local <套件名>`** |

**① 取一次任务，跑完就退出**（新机首验用这条）：

```powershell
.\.venv\Scripts\python.exe -X utf8 tools\farm_agent.py --once
```

**应该看到**：`节点 <机器名> 农场目录 \\LAPTOP-VS5F7HF4\hall-farm`。
有任务就跑完退出；没任务打 `无任务，退出` —— 这也是正常的，说明链路通了、只是还没人投任务。

**② 常驻等任务，每 30 秒去看一眼**（正式跑批用这条）：

```powershell
.\.venv\Scripts\python.exe -X utf8 tools\farm_agent.py --loop
```

**跑批期间这个窗口一直开着，别关**（关了就不取任务了）。
