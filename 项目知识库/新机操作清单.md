**这份只写动作。** 为什么这么做、报错了怎么查 → 看《测试机操作手册.md》。
每一步都带「应该看到什么」，**对不上就停下，别往下走**。

## 1. 装 Python

1. 打开 `https://www.python.org/downloads/windows/`
2. 下载 **64 位**安装包（Windows installer 64-bit）
3. 运行安装包，**第一屏最下面勾上 `Add Python to PATH`**，再点 `Install Now`
4. 装完**开一个新的 PowerShell 窗口**，敲：

   ```powershell
   python --version
   ```

**应该看到**：`Python 3.x.x`

**对不上就停**：
- 弹出微软商店 → 去 设置 → 应用 → 高级应用设置 → 应用执行别名，关掉 `python.exe` 和 `python3.exe`，回第 1 步重装
- 报 `not recognized` → 勾 PATH 那步漏了，回第 3 步重装

## 2. 把代码放到桌面

**三条路选一条。没装 Git 就走 1B。** 三条路的终点都一样，选最省事的那条。

### 1A · 有 Git（一条命令，**要外网**）

```powershell
cd C:\Users\你的用户名\Desktop
git clone https://github.com/Alvenovo/Huashuo-Dating-Automation
cd Huashuo-Dating-Automation
```

第一次会弹 GitHub 登录。先敲这行再重试：

```powershell
git config --global credential.helper manager
```

### 1B · 没 Git（**要外网**）

**先试 B-1。能打开浏览器就用它，连令牌都不用申请。**

#### B-1 · 浏览器下载（不用令牌，最省事）

1. 在这台测试机的浏览器里打开：

   ```
   https://github.com/Alvenovo/Huashuo-Dating-Automation
   ```

2. 没登录就先用**有仓库权限的账号**登录。看不到仓库 = 账号没被拉进来，回第 0 步
3. 点页面右上方的绿色 **`Code`** 按钮 → 弹出框最下面点 **`Download ZIP`**
4. 浏览器会下载一个 `Huashuo-Dating-Automation-main.zip`
5. 右键 → 全部解压缩，解压出来一个文件夹 `Huashuo-Dating-Automation-main`
6. **把文件夹改名，去掉后面的 `-main`** → `Huashuo-Dating-Automation`
7. 把它放到 `C:\Users\你的用户名\Desktop\`

**应该看到**：`C:\Users\你的用户名\Desktop\Huashuo-Dating-Automation\`

#### B-2 · 命令行下载（要一个令牌）

**只在 B-1 走不通时用**（比如这台机器不能上浏览器）。

**第 1 步：申请令牌。** 令牌就是一串代替密码的长字符串 —— GitHub 已经不允许用账号密码下载私有仓库了。
**只做一次，约 5 分钟。**

1. 用**有仓库权限的账号**登录 GitHub
2. 打开这个链接（名称和权限已经预填好了，直接改你要的就行）：

   ```
   https://github.com/settings/personal-access-tokens/new?name=hall-auto-download&description=read-only+repo+download&contents=read
   ```

   打不开就手动走一遍：右上角头像 → **Settings** → 左侧最下面 **Developer settings**
   → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**

3. **Expiration**：选 90 天（或按团队规定）
4. **Repository access**：选 **Only select repositories** → 下拉里勾上 **Huashuo-Dating-Automation**
5. **Permissions** → 展开 **Repository permissions** → 找到 **Contents** → 选 **Read-only**
   - **只要这一个权限就够了**，别多给
   - 页面上其他权限全部留 **No access**
6. 拉到底，点 **`Generate token`**
7. 页面顶部出现一串以 **`github_pat_`** 开头的字符串 —— **这就是令牌，只显示这一次，立刻复制走**

**第 2 步：用它下载。** 打开 PowerShell，一行行敲：

```powershell
$ProgressPreference = "SilentlyContinue"
[Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12
cd C:\Users\你的用户名\Desktop

$tok = Read-Host "粘贴令牌"          # 粘贴后回车，屏幕上不会显示

Invoke-WebRequest -Headers @{ Authorization = "Bearer $tok" } `
  -Uri "https://api.github.com/repos/Alvenovo/Huashuo-Dating-Automation/zipball/main" `
  -OutFile repo.zip -MaximumRedirection 5

Expand-Archive repo.zip -DestinationPath _tmp_repo
$inner = Get-ChildItem _tmp_repo | Select-Object -First 1
Move-Item $inner.FullName Huashuo-Dating-Automation
Remove-Item _tmp_repo -Recurse -Force
Remove-Item repo.zip -Force

# 清理：别把令牌留在窗口变量和命令历史里
Remove-Variable tok
Clear-History
Remove-Item (Get-PSReadlineOption).HistorySavePath -ErrorAction SilentlyContinue
```

**应该看到**：`C:\Users\你的用户名\Desktop\Huashuo-Dating-Automation\`

**报错对照**：

| 报错 | 什么原因 | 怎么办 |
| --- | --- | --- |
| `401 Unauthorized` | 令牌复制不完整，或粘贴时带了空格/换行 | 重新生成一个，`Read-Host` 那里粘贴后**别再敲空格** |
| `404 Not Found` | **权限不够时 GitHub 会假装"仓库不存在"** | 回第 2 步第 4 项，确认勾上了 `Huashuo-Dating-Automation` |
| `403 Forbidden` | 令牌过期，或 **Contents 不是 Read-only** | 回第 2 步第 5 项检查；或重新生成 |
| 卡住不动 / 重定向出错 | PowerShell 跟重定向出问题 | 改用下面这行（`curl.exe` 是系统自带的） |

```powershell
curl.exe -L -H "Authorization: Bearer $tok" -o repo.zip "https://api.github.com/repos/Alvenovo/Huashuo-Dating-Automation/zipball/main"
```

⚠️ **令牌不能写进任何文件、不能贴进聊天或群里。** 上面最后三行就是清理命令，别省。

### 1C · 无外网（**这台机器上不了外网就只能走这条**）

**你拿不到代码，得有人帮你打包。** 找组长 / 有网机器的负责人要一个压缩包。

**打包的人做这两件事**（无外网机器自己做不了）：

1. 在**有网**的机器上，把仓库放到桌面，然后跑：

   ```powershell
   cd C:\Users\有网机器的用户名\Desktop\Huashuo-Dating-Automation
   .\.venv\Scripts\python.exe -X utf8 tools\fetch_wheelhouse.py
   ```

   **应该看到**：`完成。把整个 ...\wheelhouse 目录放到共享盘 ...`
   产出的是仓库目录下一个 `wheelhouse\` 文件夹（十几个 `.whl` 加一个 `wheelhouse.json`）。

2. 打包整个仓库目录，**必须连 `wheelhouse\` 一起**。打包前**删掉这三样**：

   | 删掉 | 为什么 |
   | --- | --- |
   | `config.local.yaml` | 里面记着老机器的安装包路径，带过来会让新机器去找一个不存在的 `C:\Users\老用户名\...`，报错还长得像"共享盘坏了" |
   | `farm_node.env` | 里面是明文密码 |
   | `reports\` | 几万个文件、体积巨大，对新机器没用 |

   > **不要拷 `.venv\`。** 拷过来的 venv 会因为路径不同而起不来（报错看不出来是路径问题）。
   > 靠 `wheelhouse\` 在新机器上本机重建才是对的。

**你拿到压缩包之后：**

1. 解压到 `C:\Users\你的用户名\Desktop\`，文件夹名要是 `Huashuo-Dating-Automation`
2. 确认里面有 `wheelhouse\` 这个文件夹

**应该看到**：`C:\Users\你的用户名\Desktop\Huashuo-Dating-Automation\wheelhouse\wheelhouse.json`

⚠️ **Python 版本要对上**：`wheelhouse` 里的 wheel 是给**某一个** Python 版本下的
（比如 3.12）。你这台机器的 Python 必须和打包那台**同一个小版本**，否则装不上 ——
真装不上时 bootstrap 会明确告诉你「wheel 是给 Python 3.x 下的，本机是 3.y」，
那时候找组长要一份对应你机器版本的 `wheelhouse`，或把你的 Python 换成 3.x。

### 三条路都要做的检查

```powershell
cd C:\Users\你的用户名\Desktop\Huashuo-Dating-Automation
dir
```

**应该看到**：`AGENTS.md`、`tools`、`tests`、`hall_auto`、`config.yaml`

无外网的机器（走的 1C）还要多看到一样：`wheelhouse`

## 4. 跑铺环境脚本

**在同一个管理员窗口里**，接着敲：

```powershell
cd C:\Users\你的用户名\Desktop\Huashuo-Dating-Automation
powershell -NoProfile -ExecutionPolicy Bypass -File tools\bootstrap_machine.ps1
```

两个可选参数：

```powershell
# 节点名要用 R01 这种编号时（必须和控制机 dispatch --nodes 里写的完全一致）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\bootstrap_machine.ps1 -NodeId R01

# 系统盘空间紧张时，指到别的盘
powershell -NoProfile -ExecutionPolicy Bypass -File tools\bootstrap_machine.ps1 -InstallerDir "D:\Test\大厅"

# wheelhouse 没放在仓库目录下、也没放共享盘时，手动指路
powershell -NoProfile -ExecutionPolicy Bypass -File tools\bootstrap_machine.ps1 -Wheelhouse "D:\wheelhouse"
```

**耗时 5-15 分钟，中途别关窗口。**

⚠️ **它会打印两遍「机器铺设」，这是正常的。**
第一遍只建虚拟环境 + 装依赖，然后自动换成虚拟环境的解释器把整套重跑一遍。
第二遍开头会有一句「依赖已就绪。换用 venv 的解释器重跑整套」。
**看到这句就对了，不是重复执行。**

**应该看到**（结尾长这样）：

```
[OK] 环境自检
[OK] 虚拟环境与依赖
...
[OK] 提权计划任务
[OK] 自检 tests/unit
结果：全部通过，本机已可跑批
```

无外网的机器（走的 1C），第 2 步应该长这样 —— **关键是看到「离线」两个字**：

```
[OK] 虚拟环境与依赖
    用离线 wheelhouse：C:\...\Huashuo-Dating-Automation\wheelhouse（Python 3.12，12 个 wheel）
    离线装依赖：requirements.txt（--no-index --find-links）
    依赖安装完成，已记录标记 .deps_ok
```

**对不上就停**，把屏幕上的输出整段留好。

脚本最后会打印一个报告路径：`reports\bootstrap\bootstrap_<机器名>_<时间>.json`

**报错对照**：

| 看到什么 | 怎么办 |
| --- | --- |
| `[FAIL] 虚拟环境与依赖` + 「探不到 pip 源」 | 这台机器没外网、又没找到 `wheelhouse\`。回 1C，找组长要一份对应你 Python 版本的 `wheelhouse` 放到仓库目录下，再重跑 |
| 「wheel 是给 Python 3.12 下的，本机是 3.13」 | 你的 Python 版本和打包那台不一致。要么把你的 Python 换成 3.12，要么找组长要一份对应你版本的 `wheelhouse` |
| 「requirements.txt 改过了」 | 那份 `wheelhouse` 是旧的。找组长在有网机器上重跑一次 `fetch_wheelhouse.py` |
| 脚本在第 2 步 FAIL 之后就停了，后面步骤一条没跑 | **故意停的**。依赖没装好，后面每一步都会报假错，所以直接停。修好依赖后**重跑同一条命令**即可（做过的会跳过） |

## 接下来跑批

**取一次任务**：

```powershell
.\.venv\Scripts\python.exe -X utf8 tools\farm_agent.py --once
```

**常驻等任务**：

```powershell
.\.venv\Scripts\python.exe -X utf8 tools\farm_agent.py --loop
```

**不走共享盘，本机单跑**：

```powershell
.\.venv\Scripts\python.exe -X utf8 tools\farm_agent.py --local launch
```

跑批的完整流程（投任务 → 看进度 → 出报告）见《测试机操作手册.md》第三部分。
