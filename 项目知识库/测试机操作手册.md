# 测试机操作手册（照着做就行）

> 最后更新：2026-09-18
> 面向：拿到一台新测试机的测试人员
> 一句话：**你要做的就是「跑 3 条命令 + 填 1 个文件 + 按住屏幕别锁」**，其他全是脚本自己干。

---

## 第 0 步：先搞清楚这套东西是什么

三台角色的机器，别搞混：

| 角色 | 谁 | 干什么 |
| --- | --- | --- |
| **包源机** | 现在这台笔记本 `LAPTOP-VS5F7HF4`（`192.168.0.4`） | 存安装包 + 当"任务中转站"。**必须一直开着** |
| **控制机** | 随便一台，通常是包源机或你的办公机 | 负责投任务、看进度、出报告 |
| **测试机（节点机）** | 你要操作的新机器，可能 5 台 | 真正跑用例的那台 |

**跑批的物理过程长这样**：

```
控制机投任务 → 写到共享盘 tasks/R01.json
                      ↓
              测试机每 30 秒去共享盘看一眼
                      ↓
           有任务就取走（改名叫 .running）→ 跑用例
                      ↓
      跑完写回执 done/R01_task_xxx.json + 把证据目录拷到 results/R01/
                      ↓
              控制机汇总 → 出一张「哪台机器挂在哪条用例」的矩阵表
```

记住这个流程，后面所有"为什么要这样做"都能自己想明白。

## 第一部分：开工前的前置条件（缺一个都别开始）

### 1.0 先看清楚：哪些已经自动化了，哪些要你动手

**别把"被测的软件"和"跑测试要用的环境"搞混**，这是最容易误会的点：

| 软件 | 角色 | 自动化程度 |
| --- | --- | --- |
| **华硕大厅**（含各版本安装包） | **被测对象** | ✅ **全自动**。从共享盘取包 → 静默装 → 静默卸，P0 层全自动 |
| **网易云音乐**（P1-A 夹具） | 测试用的道具 | ✅ **全自动**。脚本驱动大厅去装/卸 |
| **7-Zip**（P1-A 更新夹具） | 测试用的道具 | ✅ **全自动**。`reset_fixture.py` 每轮自动压回钉住版本 |
| **7-Zip**（P2 解包工具） | 环境工具 | ✅ **已自动**。bootstrap 检测到没装就静默装（2026-09-18 起） |
| **Python 3.x 64 位** | 环境工具 | ❌ **必须人工**（见下面的解释） |
| **Git** | 环境工具 | ❌ **必须人工**（或让人打包拷一份） |

**为什么 Python 和 Git 自动化不了？** —— 这叫**引导悖论**：自动化脚本本身就是 Python 写的、
代码本身就是 Git 管的。没有 Python 就转不起来，没有 Git 就拉不到代码。
**这两样是"第 0 层"，只能人工铺。** 除此之外的东西，都该由脚本负责。

⚠️ **特别注意 7-Zip 出现在两个角色里**（既是测试道具、又是环境工具），
这正是容易搞混的地方。记住结论：**7-Zip 你完全不用管。**

### 1. 网络前置条件（**最容易漏，漏了就白干**）

- [ ] **测试机和控制机（包源机）在同一个局域网里**，能互相 ping 通。
  - 自测方法：在测试机上开 PowerShell，敲 `ping 192.168.0.4`，**必须看到有回复**。
  - 不通的话：可能不在同一网段、或者连的是访客 Wi-Fi（AP 隔离）。**这条路直接断了**，找 IT。

- [ ] **测试机和包源机的中断把 SMB 放行**（TCP 445 端口）。
  - 自测方法：在测试机上敲 `Test-NetConnection 192.168.0.4 -Port 445`，看 `TcpTestSucceeded` 是 `True`。
  - 是 `False`：包源机那边的防火墙规则没生效，或者中间有防火墙挡着。

- [ ] **包源机能被访问到网络共享**。
  - 自测方法：在测试机上敲 `net use \\192.168.0.4\hall-packages /user:hallshare "<密码>"`，回 `命令成功完成`。
  - 报「找不到网络路径」= 防火墙问题；报「输入的凭据无效」= 账号或密码错了；报「系统错误 53」= 网络不通。

⚠️ **重要前提：包源机必须一直开机、不休眠。** 它一关，所有测试机拿不到安装包 —— 因为官方没有下载地址，共享盘是唯一的包来源，没有兜底。

### 2. 测试机自己的前置条件

- [ ] **必须是 Windows 10/11 64 位**（32 位不行，pywinauto 访问不了 64 位进程）。
- [ ] **必须用真人登录进桌面**，**不能锁屏、不能息屏、不能断 RDP**。
  - 这是硬要求。锁屏后脚本截图全是黑屏、点击没有落点，整批用例会全部假失败。
  - 脚本会自己保持屏幕常亮（不让它睡），但**它管不了你手动按 Win+L 锁屏**，也管不了 RDP 断开。
- [ ] **7-Zip**：**不用管，脚本会自己装**（缺了 bootstrap 自动静默装钉住的 26.02）。
  - 为什么需要它：P2 安全验证要用 `7z` 解包待检安装包。
  - 只有两种情况才需要你动手：①**你没用管理员跑 bootstrap**（装到 `C:\Program Files` 需要管理员，脚本会跳过并提示）②**这台机器只跑 P2 且装失败了**。两种都会在 bootstrap 输出里明确告诉你。
- [ ] **Python 3.x 64 位** 已安装（能跑 `python --version` 就行，脚本会自己建虚拟环境）。
  - **这个没法自动化** —— 脚本本身是 Python 写的，没有 Python 就转不起来。属于"第一层"依赖，只能人工准备。
- [ ] **有管理员权限的账号**（至少一开始要，用来建计划任务、装 7-Zip）。
- [ ] **测试机上没装华硕大厅**，或者装了也行（脚本会先卸再装）。
- [ ] **屏幕缩放不用管**，150% / 125% / 100% 都不影响正确性。**千万不要手动改成 100%**，改了反而没用（脚本走物理像素）。

### 3. 要提前拿到的三样东西（找组长/负责人要）

| 东西 | 说明 | 放哪 |
| --- | --- | --- |
| **共享盘账号密码** | 账号通常叫 `hallshare` | 用的时候临时设成环境变量，**别写进任何文件** |
| **测试账号 + 密码** | 华硕大厅的登录账号，只有 1 个，多机同时登录不会互踢 | 填到测试机本地的 `farm_node.env` |
| **微软邮箱**（可选） | 如果这台机器要跑微软 SSO 免密登录用例 | 同上 |

⚠️ **密码规则（红线，别踩）**：
- 密码**只走环境变量或本机 `farm_node.env`**，那个文件已经在 `.gitignore` 里。
- **绝对不许**把密码写进共享盘任务文件、不许写进 git、不许贴到聊天里。
- 任务文件里如果混进了密码，脚本会**直接拒绝这个任务**，不会偷偷忽略。

## 第二部分：新测试机操作步骤（按顺序做，别跳）

### 步骤 1：把代码搞到测试机上

```powershell
cd C:\Users\你的用户名\Desktop
git clone <仓库地址> Huashuo-Dating-Automation
cd Huashuo-Dating-Automation
```

**预期结果**：目录里能看到 `AGENTS.md`、`tools\`、`tests\`、`hall_auto\` 这些文件夹。

**如果报找不到 git**：先装 Git for Windows，或者让有仓库的人打包一份拷过去。

---

### 步骤 2：跑铺环境脚本（**核心步骤，只做一次**）

**先设共享盘凭据**（这样脚本能连上共享盘）：
```powershell
$env:HALL_SHARE_USER = "hallshare"
$env:HALL_SHARE_PASSWORD = "<共享盘密码>"
```

**然后用管理员 PowerShell 跑**（开始菜单右键 → 终端(管理员) / Windows PowerShell(管理员)）：
```powershell
cd C:\Users\你的用户名\Desktop\Huashuo-Dating-Automation
powershell -NoProfile -ExecutionPolicy Bypass -File tools\bootstrap_machine.ps1
```

**这一步要跑多久？** 第一次大概 5-15 分钟（要建虚拟环境、装依赖、从共享盘拷 400MB 的安装包）。**中途别关窗口**。

**脚本会依次做这 11 件事**（它会自己判断，已经有跳过的，不会重复做）：

| # | 它做什么 | 你要看什么 |
| --- | --- | --- |
| 1 | 环境自检 | 检查系统版本、是不是 64 位 Python、有没有 7-Zip、是不是解锁桌面 |
| 2 | 建虚拟环境 + 装依赖 | 第一次会 pip 装 5 个包，慢是正常的 |
| 3 | 校验夹具文件完整性 | 检查 7-Zip 夹具包的 sha256 对不对 |
| 4 | **7-Zip**（缺了自动装） | 没装就静默装钉住版 26.02；已装就跳过，一个动作都不做 |
| 5 | 生成这台机器的配置 `config.local.yaml` | 把安装包路径改成这台机器的真实路径 |
| 6 | **生成凭据文件模板 `farm_node.env`** | 只生成空模板！**值要你自己填**（见步骤 3） |
| 7 | 连共享盘 | 用你刚才设的环境变量去连 |
| 8 | 准备农场目录 `tasks/ done/ results/ logs/` | |
| 9 | 准备安装包 | 本地有就用本地的，没有就从共享盘拷 |
| 10 | **建提权计划任务 `HallAutoP1`** | 这一步必须管理员，否则会 FAIL |
| 11 | 跑单元测试自检 | 全绿说明环境 OK |

**预期结果**（结尾长这样）：
```
[OK  ] 环境自检
[OK  ] 虚拟环境与依赖
...
[OK  ] 提权计划任务
[OK  ] 单元测试自检
结果：全部通过
```

脚本最后会打印一个报告文件的路径：`reports\bootstrap\bootstrap_<机器名>_<时间>.json`。

**❗ 三种可能的报错，这样处理**：

| 报错 | 什么意思 | 怎么办 |
| --- | --- | --- |
| 第 9 步 FAIL「非管理员无法建计划任务」 | 你没用管理员身份跑 | 关掉窗口，重新用**管理员** PowerShell 跑一遍。幂等的，前面做过的会跳过 |
| 第 2 步 FAIL「pip install 失败」 | 网不通或者 pip 源有问题 | 检查测试机能不能上外网 |
| 第 1 步 FAIL「非交互式会话」 | 屏幕锁了 / RDP 断了 | 把屏幕解锁，重跑 |
| 第 1 步只是提示「未装 7-Zip」 | 不是错误 | 下一步会自动装。若下一步也没装成功，会告诉你原因（多半是没用管理员） |
| 第 4 步「未装 7-Zip 且当前非管理员」 | 装到 `C:\Program Files` 要管理员 | 用管理员重跑一遍即可。**不影响其他套件**，只影响 P2 |
| 第 3 步只是提示「暂无 7-Zip 更新夹具包」 | 不是错误 | 下一步会从官方源取 |

**为什么要跑这一步？** 因为仓库里默认的配置写的是占位假路径 `C:/Users/ASUS/Desktop/华硕大厅`。不跑 bootstrap 的话，脚本会去这个不存在的路径找安装包 → 找不到 → 想下载 → 但没有下载地址 → **直接失败**。

**这一步可以重复跑吗？** 可以。脚本是幂等的，第二次跑会全部跳过，只花十几秒。

### 步骤 3：填凭据文件（**这一步必须人工，脚本故意不代劳**）

打开测试机上的 `farm_node.env`（就在项目根目录里），长这样：

```ini
# --- 登录套件（P1-B）---
HALL_TEST_USER=
HALL_TEST_PASSWORD=
# 微软 SSO 免密用例
HALL_MS_USER=
# 改密码往返用例（只在人在环时用）
HALL_TEST_NEW_PASSWORD=

# --- 共享盘取包 ---
HALL_SHARE_USER=
HALL_SHARE_PASSWORD=
```

**你要做的**：把等号后面填上真实值。比如：
```ini
HALL_TEST_USER=hall_test_001
HALL_TEST_PASSWORD=xxxxxx
HALL_MS_USER=someone@outlook.com
HALL_SHARE_USER=hallshare
HALL_SHARE_PASSWORD=xxxxxx
```

**规则**：
- 值**不要加引号**。
- 用不上的留空就行，对应套件会自动跳过，**不影响其他套件**。
- **不需要重跑 bootstrap**。脚本每次取任务时会重新读这个文件。

**❗ 为什么不填就出事**：
登录套件（`login`）跑起来会**静默跳过** —— 不报错，但一条都没真正跑。报告上看起来是黄色（跳过），如果不看凭据列，你会以为"跑过了没问题"，其实是**什么都没验证**。

**预期结果**：文件保存后，可以敲这行验证一下能不能读到：
```powershell
.\.venv\Scripts\python.exe -c "from hall_auto.env_pack import build_suite_env, credential_status; env,_=build_suite_env(); print(credential_status(env))"
```
应该看到 `password_login: True` 之类（填了就是 True，没填是 False）。

### 步骤 4：手工验证一下能连上共享盘农场

```powershell
net use \\192.168.0.4\hall-farm /user:hallshare "<共享盘密码>" /persistent:yes
dir \\192.168.0.4\hall-farm
```

**预期结果**：能看到 `tasks`、`done`、`results`、`logs` 四个文件夹。

**看不到怎么办**：

## 第三部分：控制机（你）要做的三件事

**先设农场目录**（每次开新窗口都要设）：
```powershell
$env:HALL_FARM_ROOT = "\\192.168.0.4\hall-farm"
```

### 3.1 投任务

```powershell
.\.venv\Scripts\python.exe -X utf8 tools\farm_control.py dispatch --nodes R01,R02,R03,R04,R05 --suites launch,apps-detect
```

**参数说明**：
- `--nodes`：测试机的节点名字，逗号分隔。**要和测试机的 `node_id` 对得上**（默认是主机名，也可以用 bootstrap 的 `--node-id` 指定）。
- `--suites`：要跑哪些套件，逗号分隔。**可用套件名单**：

| 套件名 | 跑什么 | 需要什么前提 | 大概多久 |
| --- | --- | --- | --- |
| `unit` | 单元测试（纯逻辑，不碰界面） | 无 | 1 分钟 |
| `install` | 安装/卸载华硕大厅 | **管理员 + `HALL_ALLOW_INSTALL=1`** | 15-20 分钟 |
| `launch` | 启动冒烟 + 搜索（P0） | 已装大厅 | 3-5 分钟 |
| `apps-detect` | 应用列表检测（只读，不装东西） | 已装大厅 | 3 分钟 |
| `apps-lifecycle` | 真装真卸第三方应用 | **管理员 + `HALL_ALLOW_INSTALL=1`** | 10-15 分钟 |
| `login` | 登录 + 注册（P1-B） | **需要测试账号** | 5 分钟 |
| `login-manual` | 短信登录 / 改密码（**人在环，永不进农场**） | 要真人守着 | 5 分钟 |
| `settings` | 主题切换（P1-C） | 已装大厅 | 2 分钟 |
| `security` | 安装包签名验证（P2） | 内部安全工具已放到本机 | 1 分钟 |
| `wb` | WorkBuddy 入口（P2） | WB 后台开关已开、WB 未安装 | 1-2 分钟 |

**预期结果**：
```
R01: 2 个套件 -> R01.json
R02: 2 个套件 -> R02.json
...
任务 task_20260918_180000 已投给 5 台节点（共 5 台）。

并发预算：
  launch 全并行（不碰服务端）
  apps-detect 全并行（不碰服务端）
```

⚠️ **那句"并发预算"别忽略**，它告诉你哪些套件被限流了。

### 3.2 叫测试机开跑

**方式 A（推荐，一次性）**：在每台测试机上跑：
```powershell
.\.venv\Scripts\python.exe -X utf8 tools\farm_agent.py --once
```
取一次任务，跑完就退出。

**方式 B（常驻，无人值守）**：
```powershell
.\.venv\Scripts\python.exe -X utf8 tools\farm_agent.py --loop
```
每 30 秒去共享盘看一眼，有任务就跑。**跑批期间让这个窗口一直开着**。

**测试机那边的预期输出**：
```
节点 R01 农场目录 \\192.168.0.4\hall-farm
取到任务 task_20260918_180000
  跑 launch（分片 1/1）
  跑 apps-detect（分片 1/1）
  证据已回传 \\192.168.0.4\hall-farm\results\R01\R01_2026-09-18_1800
任务完成，结果 \\192.168.0.4\hall-farm\done\R01_task_20260918_180000.json
```

**如果打印「无任务，退出」**：说明控制机还没投任务，或者投的节点名和这台机器对不上。先检查 `node_id`。

## 第四部分：跑批过程中，测试人员要盯着什么

### 必须做的

| 项目 | 为什么 |
| --- | --- |
| **别锁屏、别合盖、别关显示器** | 锁屏后截图全黑、点击没落点，整批用例假失败。脚本只能保屏幕常亮，管不了你手动锁 |
| **别断 RDP** | RDP 一断，Windows 会话变非交互态，脚本会直接报错退出（这是故意的，比产出一堆假数据好） |
| **别在测试机上手动操作** | 脚本在点鼠标键盘，你一动就会互相干扰 |
| **别关测试机的 agent 窗口**（如果用 `--loop`） | 关了就不取任务了 |
| **确保包源机不关机** | 它一关，正在跑的机器取不到包 |

### 会看到什么现象（正常，别慌）

| 现象 | 正常吗 | 说明 |
| --- | --- | --- |
| 屏幕忽明忽暗 | ✅ 正常 | `settings` 套件在切主题 |
| 大厅自己启动又自己关 | ✅ 正常 | 各套件在跑 |
| 有几个软件被装上又卸掉 | ✅ 正常 | `apps-lifecycle` 在真装真卸夹具应用 |
| 报告里一片黄（skip） | ⚠️ 要看原因 | 看报告里的「凭据」列：✗ 说明这台机器没配凭据；✓ 说明是用例本身在跳过 |
| 整批突然停在某个点 | ❌ 要查 | agent 可能挂了。看测试机的 `farm_root\logs\<节点>_<任务>.log` |

### 绝对不能做的（**点了就出事**）

- **绝对不要在大厅界面上点「全部安装」**。列表里全是 QQ / 微信 / WPS 这类日常软件，点下去就真装一机器。
- **绝对不要**在没有 `HALL_ALLOW_INSTALL=1` 的机器上跑 `install` / `apps-lifecycle` 套件（脚本会自动 skip 掉，但别硬绕）。
- **办公机永远别开 `HALL_ALLOW_INSTALL`**。

## 第六部分：出问题怎么查（对照表）

### 测试机侧

| 现象 | 大概率原因 | 怎么解 |
| --- | --- | --- |
| agent 一直说「无任务」，但控制机明明投了 | ①节点名对不上 ②上一轮进程被杀留下 `.running` 占位挡住了 | ①确认 `node_id` 和 `--nodes` 一致 ②agent 启动时会自动清残留，重跑一次；还不行就看 `tasks\` 下有没有 `.running` 文件 |
| 控制机说投给 5 台，只有 3 台取到 | 另 2 台网络不通或 agent 没起 | 去那 2 台检查 `net use` 和 agent 进程 |
| 用例大批失败且截图全黑 | **屏幕锁了 / RDP 断了** | 解锁屏幕重跑。这是最常见的原因 |
| 登录用例全 skip | `farm_node.env` 没填凭据 | 填上（见步骤 3） |
| 报「找不到安装包」 | 没跑 bootstrap，还在读假路径 `C:/Users/ASUS/...` | 跑 bootstrap |
| 报「拿不到包，已阻止卸载」 | 共享盘不通 + 没有下载地址 | 检查包源机是否开着、网络是否通 |
| 装到一半失败 | 权限不够 | `install` 套件要管理员 + 计划任务 `HallAutoP1` |
| 找不到 `HallAutoP1` 计划任务 | bootstrap 第 9 步失败 | 用管理员重跑 bootstrap |

### 共享盘侧

| 现象 | 原因 | 怎么解 |
| --- | --- | --- |
| `dir` 没任何输出也不报错 | **目录是空的**，不是失败 | 放个文件再试 |
| 「找不到网络路径」 | 防火墙挡了 445 | 包源机放行 445 |
| 「输入的凭据无效」 | 用了没密码的账号 | 必须用带密码的 `hallshare` 账号 |
| 「拒绝访问」 | 共享权限没给对 | `hall-farm` 要 **Change**，`hall-packages` 要 **Read** |
| `ping` 都不通 | AP 隔离 / 不同网段 | 这条路断了，找 IT |

## 第七部分：一次性准备工作（只做一次，做完全部机器共用）

⚠️ **这一步要人工，而且必须用管理员身份。** 原因是：建 SMB 共享是内核级的特权操作，非管理员进程会报「系统错误 5 拒绝访问」，而且 UAC 那个「是」的确认框画在安全桌面上，非管理员进程根本碰不到 —— 这是唯一绕不过去的硬墙。**但只需按这一次**，5 台机器共用，不用每台都提权。

**在包源机上，用管理员 PowerShell 跑**：
```powershell
cd C:\Users\你的用户名\Desktop\Huashuo-Dating-Automation
powershell -NoProfile -ExecutionPolicy Bypass -File tools\provision_share.ps1 -SharePassword "<共享账号密码>"
```

**它会做 5 件事**：
1. 确保 `hallshare` 账号存在（不存在就建）
2. 建 `hall-packages` 共享（**Read** 权限）+ `hall-farm` 共享（**Change** 权限）
3. 配 NTFS 权限
4. 放行防火墙 TCP 445
5. 建农场四个目录 `tasks/ done/ results/ logs/`
6. 最后自测一遍网络路径能不能通

**预期结果**：
```
[OK  ] share account hallshare
[OK  ] share hall-packages
[OK  ] hall-packages -> hallshare = Read
[OK  ] share hall-farm
[OK  ] hall-farm -> hallshare = Change
[OK  ] NTFS C:\hall-farm -> hallshare = Modify
[OK  ] farm subdirectories
[OK  ] firewall HallShare-SMB
=== verification (network path, as a node sees it) ===
[OK  ] reachable \\LAPTOP-VS5F7HF4\hall-packages
[OK  ] reachable \\LAPTOP-VS5F7HF4\hall-farm
RESULT: OK
Shares are ready.
```

**退出码**：`0` = 成功 / `2` = 不是管理员 / `1` = 有失败项。

**❗ 报错这样处理**：

| 报错 | 怎么办 |
| --- | --- |
| `RESULT: NOT_ELEVATED`，退出码 2 | 你没用管理员。重新开管理员 PowerShell |
| `RESULT: NO_SHARE_ACCOUNT` | `hallshare` 账号不存在而且你没给 `-SharePassword`。加上 `-SharePassword "<密码>"` 重跑 |
| `[FAIL] reachable \\...\hall-farm` | 共享建好了但本机访问不到，通常是防火墙。检查 `Get-NetFirewallRule -DisplayName "HallShare-SMB"` |
| 末尾不是 `RESULT: OK` | 上面一定有 `[FAIL]` 行，按那行的提示处理 |

⚠️ **`hall-farm` 为什么必须给 Change 而不是 Read**：节点要改任务文件名（取走任务）、要写回执、要推证据目录。给 Read 的话这些操作会**静默失败** —— 不报错，但任务永远取不走，你会查到怀疑人生。

## 附录 C：几个必须知道的"为什么"

**为什么新机器第一步永远是 bootstrap？**
仓库里默认配置写的是占位路径 `C:/Users/ASUS/Desktop/华硕大厅`，实际不存在的路径。bootstrap 才会把这个路径改成这台机器的真实路径。不跑就找不到包。

**为什么凭据要手填、不自动导出？**
红线是「密码不落盘、不进 git」。自动从环境变量导出到文件，等于把本来是临时的密码写死在磁盘上了。所以脚本只生成一个空模板，落盘这个动作由人显式决定。

**为什么不用映射盘符（`Z:`）？**
映射盘符是跟登录会话绑的。计划任务和服务跑在另一个会话里，看不到你映射的 `Z:`。UNC 路径（`\\机器名\共享名`）没有这个问题。所以配置里一律写 UNC。

**为什么用机器名而不是 IP？**
DHCP 分配的 IP 重启会变。用机器名稳一些（前提是局域网名字解析正常）。

**为什么 `login-manual` 套件永远不进农场？**
因为它要真人守着（短信验证码、改密码），无人值守跑不了，硬跑只会卡在 `input()` 上。

**为什么登录用例没凭据是"静默跳过"而不是"报错"？**
因为设计上允许一台机器只跑不需要凭据的套件。但代价是容易误判 —— 所以报告里专门有「凭据」列来区分「没配凭据」和「用例本身在跳过」，看报告时记得看那列。
