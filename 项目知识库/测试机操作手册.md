## 第 0 步：先搞清楚这套东西是什么

三台角色的机器，别搞混：

| 角色 | 谁 | 干什么 |
| --- | --- | --- |
| **包源机** | 现在这台笔记本 `LAPTOP-VS5F7HF4` | 存安装包 + 当"任务中转站"。**必须一直开着** |
| **控制机** | 随便一台，通常是包源机或你的办公机 | 负责投任务、看进度、出报告 |
| **测试机（节点机）** | 你要操作的新机器，可能 5 台 | 真正跑用例的那台 |

**跑批的物理过程长这样**：

```
控制机投任务 → 写到共享盘 tasks/R01.json
                      ↓
              测试机每 30 秒去共享盘看一眼
                      ↓
           有任务就取走（改名叫 .running）→ 跑用例
                      ↓
      跑完写回执 done/R01_task_xxx.json + 把证据目录拷到 results/R01/
                      ↓
              控制机汇总 → 出一张「哪台机器挂在哪条用例」的矩阵表
```

记住这个流程，后面所有"为什么要这样做"都能自己想明白。

## ⚠️ 开工前必做（**只做一次，做完全部机器共用**）

**在包源机上，用管理员 PowerShell 跑一次**（完整说明见第七部分）：

```powershell
cd C:\Users\你的用户名\Desktop\Huashuo-Dating-Automation
$env:HALL_SHARE_PASSWORD = "<共享账号密码>"      # 密码只走环境变量，别写进文件
powershell -NoProfile -ExecutionPolicy Bypass -File tools\provision_share.ps1
```
（也可以写成 `... provision_share.ps1 -SharePassword "<密码>"`，两种都行。
**推荐环境变量**：`HALL_SHARE_PASSWORD` 是节点机 `net use` 用的同一个变量，设一次就够。）

⚠️ **三行要一起执行，`cd` 不能省。** 不在仓库根目录跑会报
`-File 形式参数的实际参数"tools\provision_share.ps1"不存在` —— 这个报错读起来像"脚本没了"，
实际只是当前目录不对，不是文件缺失。

**为什么这件事排在最前面**：它负责在包源机上建出 `hall-farm` 共享（任务中转站）。
**没做这一步，后面所有测试机都连不上农场、取不到任务** —— 而且报错是"找不到网络路径"，
看起来像网络问题，实际是共享没建。**先做完这一步，再往下走。**

（如果你确认这个共享已经建好了 —— 在包源机上敲 `net share` 能看到 `hall-farm` —— 就跳过这里。）

## 第一部分：开工前的前置条件（缺一个都别开始）

### 1.0 先看清楚：哪些已经自动化了，哪些要你动手

**别把"被测的软件"和"跑测试要用的环境"搞混**，这是最容易误会的点：

| 软件 | 角色 | 自动化程度 |
| --- | --- | --- |
| **华硕大厅**（含各版本安装包） | **被测对象** | ✅ **全自动**。从共享盘取包 → 静默装 → 静默卸，P0 层全自动 |
| **网易云音乐**（P1-A 夹具） | 测试用的道具 | ✅ **全自动**。脚本驱动大厅去装/卸 |
| **7-Zip**（P1-A 更新夹具） | 测试用的道具 | ✅ **全自动**。`reset_fixture.py` 每轮自动压回钉住版本 |
| **7-Zip**（P2 解包工具） | 环境工具 | ✅ **已自动**。bootstrap 检测到没装就静默装（2026-09-18 起） |
| **内部安全工具**（P2 的 CheckAppV 等） | 环境工具 | ✅ **已自动**。bootstrap 从共享盘拷到本机（2026-09-18 起）。**它不进公开仓库，但可以放共享盘** —— 共享盘不是 git |
| **Python 3.12 64 位** | 环境工具 | ❌ **必须人工**（见下面的解释）。**版本必须 3.12** —— 共享盘的离线依赖包是给 3.12 打的 |
| **Git** | 环境工具 | ✅ **一行命令自动装**（2026-09-21 起）。从共享盘静默装，**不需要外网、不需要令牌**，见步骤 1 |
| **磁盘可用空间 ≥ 3 GB** | 环境工具 | ✅ **已自动检查**。bootstrap 第 1 步会报剩余空间，低于 3 GB 明确警告 |
| **pip 源 / 外网** | 环境工具 | ⚠️ **只在第 2 步用一次，且可以先离线**。bootstrap **先找离线 wheelhouse**（`--wheelhouse` / 仓库下 `wheelhouse\` / 共享盘 `wheelhouse\`），找到就直接 `--no-index` 装，**完全不碰网络**；找不到才去探 pip 源。**铺完之后跑批完全不需要外网**。⚠️ **"可以先离线"的前提是 Python 装的是 3.12**（见上一行）—— 版本不对，离线包就用不了 |

**为什么 Python 自动化不了？** —— 这叫**引导悖论**：自动化脚本本身就是 Python 写的，
没有 Python 就转不起来。**Python 是唯一真正绕不开的第 0 层。**

Git 也踩同一个死锁（拿代码要先有 Git，可脚本要先有代码才能跑）—— 但它**有解**：
共享盘上放了一个**不依赖任何东西**的安装脚本，一行命令装好，之后就能 `git clone`。
所以 Git **不用你手动装，也不用外网、不用令牌**。这就是步骤 1 路线 A 的 A-1。

**所以你要动手的事，其实只有这 3 件**（其余全部自动，**包括装 Git**、装 7-Zip、装依赖、取包、建计划任务）：

| # | 你要做的事 | 能省掉吗 |
| --- | --- | --- |
| 1 | 装 **Python 3.12 64 位**，安装时**勾上 "Add Python to PATH"** | ❌ **省不掉** —— 唯一的硬门槛，脚本本身是 Python 写的。**版本也省不掉**：离线依赖包是 3.12 的 |
| 2 | 找组长/负责人要 **3 样凭据**（共享盘账号密码、大厅测试账号密码、微软邮箱〔可选〕） | ❌ 省不掉 —— 脚本**故意不代劳**，密码是红线 |
| 3 | 开一个**管理员** PowerShell，跑一次 bootstrap | ❌ 省不掉 —— 第 4 步装 7-Zip、第 11 步建计划任务都要管理员 |

**"配合输入命令行"这个说法要修正一下**：真正要敲的命令就那么几条
（步骤 1 装 Git + 拉代码，步骤 2 设 3 个环境变量 + 跑 bootstrap），
而且**必须先开管理员窗口、再在窗口里设变量**。
另外还要**手工编辑一次 `farm_node.env`**（步骤 3）—— 那不是敲命令，是填文件。

⚠️ **特别注意 7-Zip 出现在两个角色里**（既是测试道具、又是环境工具），
这正是容易搞混的地方。记住结论：**7-Zip 你完全不用管。**

### 1. 网络前置条件（**最容易漏，漏了就白干**）

- [ ] ⚠️ **两台机器上的代理 / VPN / 加速器全部关掉，TUN 模式尤其要关。这一条排第一位。**
  2026-09-22 实测：TUN 开着时 `\\LAPTOP-VS5F7HF4` 的名字解析被劫持，共享盘直接报
  「**系统错误 53** 找不到网络路径」—— 看着像防火墙坏了、共享盘挂了，**实际是代理**。
  - 自测方法（**控制机和测试机都要查**，下面两条都应该是空的）：
    ```powershell
    tasklist | findstr /i "clash mihomo v2ray sing-box verge"
    ipconfig /all | findstr /i "198.18 Mihomo Tunnel"
    ```
  - 第二条出现 `Mihomo` / `Meta Tunnel` / `198.18.0.1` = **TUN 虚拟网卡还挂着**，
    说明只关了开关没关干净。去代理软件里关掉 TUN（或整个退出），再重查一遍。

- [ ] **测试机和控制机（包源机）在同一个局域网里**，能互相 ping 通。
  - 自测方法：在测试机上开 PowerShell，敲 `ping LAPTOP-VS5F7HF4`，**必须看到有回复**。
  - 不通的话：可能不在同一网段、或者连的是访客 Wi-Fi（AP 隔离）。**这条路直接断了**，找 IT。

- [ ] **测试机和包源机两端都要放行 SMB**（TCP 445 端口）。
  - 自测方法：在测试机上敲 `Test-NetConnection LAPTOP-VS5F7HF4 -Port 445`，看 `TcpTestSucceeded` 是 `True`。
  - 是 `False`：包源机那边的防火墙规则没生效，或者中间有防火墙挡着。

- [ ] **包源机能被访问到网络共享** —— ⚠️ **这一条不是"自测"，是必做动作。**
  新机器**默认连不上**共享盘（NTFS 只授权了 `hallshare` 账号，你本机账号在网络上是"别人"），
  而后面装 Git、拉代码、取安装包、连农场**全靠它**。照 **第二部分 步骤 1 的 A-0** 做一次，
  回 `命令成功完成` 才算过。
  - **报错对照表**（`net use` 报错是英文的，对照着看）：

    | 你看到的 | 真因 | 怎么办 |
    | --- | --- | --- |
    | `系统错误 53` 找不到网络路径 | **代理/TUN 没关**（最常见），或网络真不通 | 先按上面第 1 条查代理，再 `ping -4 LAPTOP-VS5F7HF4` |
    | `系统错误 1219` 同一用户不能用多个用户名连同一服务器 | 这台机器上**已经有**一条到控制机的连接（多半看不见） | 管理员窗口跑 `Restart-Service LanmanWorkstation -Force`，再重试 |
    | `系统错误 1909` 帐户当前已锁定 | `hallshare` 被锁了（反复认证失败撞的） | **等 10 分钟**（锁定期），别连着试 —— 每试一次重新计 10 分钟 |
    | `系统错误 1326` 用户名或密码错误 | 密码不对，**或用了轮换前的旧密码** | 核对凭据；清 `net use` + `cmdkey` 里的旧条目 |
    | `系统错误 67` 找不到网络名 | 地址写成了 **IP**，DHCP 换过 | 改回机器名 |
    | 输入的凭据无效 / 拒绝访问 | 账号密码错 / 用的**不是 `hallshare`** | 见 A-0 的表 |

    ⚠️ **清隐式连接**（1219 的解药，`net use` 看不到这种连接）：
    ```powershell
    Restart-Service LanmanWorkstation -Force
    Get-SmbConnection
    ```
    嫌麻烦就直接**重启这台机器** —— 一次把连接和 10 分钟锁定窗口都耗掉。

- [ ] **这台测试机能访问 pip 源**（**只在第 2 步用一次**）。
  - 自测方法：在测试机上敲 `Test-NetConnection pypi.org -Port 443`，看 `TcpTestSucceeded` 是 `True`。
  - **装了 3.12 的机器：不通也不卡死**（走下面第 1 条离线包），但要提前知道。
    ⚠️ **装了 3.13/3.14 的机器：这条不通就是死路** —— 离线包是 `cp312`，装不上，
    在线源又不通，bootstrap 第 2 步会直接 FAIL 停住。**先去把 Python 换成 3.12。**
  - 三条绕法（bootstrap 报错时也会打印前两条）：
    1. **离线 wheelhouse（无外网机器的正道）**：**共享盘 `hall-packages\wheelhouse\` 上已经备好一份**
       （2026-09-21 起，Python 3.12），bootstrap 会自己找到并离线装，**你什么都不用做**。
       要重做/换 Python 版本时，在有网机器上跑
       `python -X utf8 tools\fetch_wheelhouse.py --to "C:\hall-packages\wheelhouse"`。
       也可以放到**仓库根目录**下、`installer_dir` 下，或直接 `--wheelhouse "D:\wheelhouse"` 指路。
    2. 用公司内网镜像：`pip config set global.index-url <镜像地址>`，然后重跑 bootstrap。
    3. ~~从已铺好的机器整份拷 `.venv` + `--skip-venv`~~ —— **已废弃**，见下面的说明。
  - 铺完之后**跑批不再需要外网**：安装包走共享盘，7-Zip 夹具包共享盘上也有。

⚠️ **为什么废弃了「整份拷 `.venv`」**（2026-09-21 核过，别再用）：
`.venv\pyvenv.cfg` 里的 `home` 指向**原机器**的 Python 安装路径，`.venv\Scripts\pip.exe` /
`pytest.exe` 这些启动器里又写死了**原 venv 的绝对路径**。新机器上用户名或 Python 安装位置
只要有一处不同，拷过去的 venv 就起不来 —— 而且报错看不出来是路径问题。
所以现在 bootstrap 的 `--skip-venv` 也改成**实测依赖能不能用**了，不再"文件在就跳过"；
真拷了坏 venv 会当场被点出来并本机重建。

⚠️ **重要前提：包源机必须一直开机、不休眠。** 它一关，所有测试机拿不到安装包 —— 因为官方没有下载地址，共享盘是唯一的包来源，没有兜底。

### 2. 测试机自己的前置条件

- [ ] **必须是 Windows 10/11 64 位**（32 位不行，pywinauto 访问不了 64 位进程）。
- [ ] **必须用真人登录进桌面**，**不能锁屏、不能息屏、不能断 RDP**。
  - 这是硬要求。锁屏后脚本截图全是黑屏、点击没有落点，整批用例会全部假失败。
  - 脚本会自己保持屏幕常亮（不让它睡），但**它管不了你手动按 Win+L 锁屏**，也管不了 RDP 断开。
- [ ] **7-Zip**：**不用管，脚本会自己装**（缺了 bootstrap 自动静默装钉住的 26.02）。
  - 为什么需要它：P2 安全验证要用 `7z` 解包待检安装包。
  - 只有两种情况才需要你动手：①**你没用管理员跑 bootstrap**（装到 `C:\Program Files` 需要管理员，脚本会跳过并提示）②**这台机器只跑 P2 且装失败了**。两种都会在 bootstrap 输出里明确告诉你。
- [ ] **Python 3.12 64 位** 已安装（能跑 `python --version` 并打出 `Python 3.12.x`；脚本会自己建虚拟环境）。
  - ⚠️ **必须是 3.12，不是"3.x 随便"**：共享盘的离线依赖包（`wheelhouse\`）是给 3.12 打的。
    装了 3.13/3.14 的机器**没外网时会在 bootstrap 第 2 步卡死**（离线包用不了、在线又探不到 pip 源）。
    有外网也别混装 —— 理由见 1.0 的「pip 源 / 外网」那行。
  - 想省下载：**先做完第 2 部分步骤 1 的 A-0（连共享盘）**，共享盘上就有这个安装包
    `\\LAPTOP-VS5F7HF4\hall-packages\wheelhouse\python-3.12.10-amd64.exe`。
  - **这个没法自动化** —— 脚本本身是 Python 写的，没有 Python 就转不起来。属于"第 0 层"依赖，只能人工准备。
    （它是**唯一**真正绕不开的：Git 现在由共享盘上一行脚本自动装，见步骤 1 路线 A。）
  - ⚠️ **必须能在命令行里敲 `python` 就出来**（也就是在 PATH 里）。装了但 PATH 没配的话，
    新机器第一次跑 bootstrap 会直接失败 —— 因为它要先用系统 Python 建虚拟环境。
    自测：开个新 PowerShell 敲 `python --version`，能打印版本号才算过。装的时候记得勾
    "Add Python to PATH"。
  - **bootstrap 会给你中文报错，不用猜**。第 1 步之前它会先找 Python，三种情况都有明确提示：
    | 情况 | 你会看到 |
    | --- | --- |
    | 没装 / 没勾 PATH | `[FAIL] 这台机器上找不到可用的 Python` + 安装地址 + "务必勾 Add Python to PATH" |
    | PATH 上只有 `py` 启动器 | `[提醒] python 不在 PATH 里，本次改用 py 启动器顶上`（**能跑**，但手册的自检会失败，建议补上 PATH） |
    | 敲 `python` 弹微软商店 | `[FAIL]` + 点明这是「应用执行别名」桩，并给出关掉它的路径 |
  - ⚠️ **「应用执行别名」是个真陷阱**：Windows 自带一个假的 `python.exe` 桩（在
    `...\WindowsApps\` 下），敲 `python` 会弹微软商店。**它看着像装了 Python，其实没装。**
    自测时如果弹出商店，去 设置 → 应用 → 高级应用设置 → 应用执行别名，把
    `python.exe` / `python3.exe` 关掉，再装真 Python。
- [ ] **有管理员权限的账号**（至少一开始要，用来建计划任务、装 7-Zip）。
- [ ] **测试机上没装华硕大厅**，或者装了也行（脚本会先卸再装）。
- [ ] **屏幕缩放不用管**，150% / 125% / 100% 都不影响正确性。**千万不要手动改成 100%**，改了反而没用（脚本走物理像素）。
- [ ] **系统盘（或你指定的安装盘）至少留 3 GB 可用空间**。**脚本会自己检查并告诉你**（bootstrap 第 1 步）。
  - 为什么：安装包缓存约 800MB、装上去的大厅本体几百 MB、加上证据截图。

### 步骤 1：把代码搞到测试机上

**Python 一定要先装好**（脚本自己装不了，见 1.0）：
在 PowerShell 里敲 `python --version`，**能打印版本号才算过**

#### 路线 A（推荐）：从共享盘 clone

**A-0 先连共享盘（必做）。** 共享要 `hallshare` 账号才能进，**新机器默认进不去** ——
不先认证，A-1 / A-2 会报「找不到网络路径」或「拒绝访问」，而那条报错会把人引向"网络坏了"。

**应该看到**：第一行 `命令成功完成。`；第二行列出 `hall-auto.git`、`Git-2.55.0.5-64-bit.exe`、`install_git.ps1`。

| 看到什么 | 什么意思 | 怎么办 |
| --- | --- | --- |
| 系统错误 53 / 找不到网络路径 | 网络或防火墙不通（445 被挡、不同网段、机器名解析不了） | `ping LAPTOP-VS5F7HF4` → `Test-NetConnection LAPTOP-VS5F7HF4 -Port 445`；是 `False` 就找组长放行 445 |
| 系统错误 67 / 找不到网络名 | 共享名写错，或共享没建 | 核对是 `hall-packages`；包源机敲 `net share` 能看到它 |
| 系统错误 1326 / 登录失败 | 密码不对（`hallshare` 密码被重置过） | 找组长要当前密码 |
| 拒绝访问（错误 5） | 网络通，但用的**不是 `hallshare` 账号** | **别在资源管理器里点进去输别的账号**；在要用的那个窗口里重跑本步命令 |
| 系统错误 1219 / 多重连接冲突 | 已用别的账号连过包源机了 | 先 `net use * /delete /y`，再重跑本步 |

**三点要知道的**：

- `/persistent:yes` = 重启后自动重连。密码交给 Windows 凭据管理器（DPAPI 加密），**不是明文落盘** ——
  红线是"密码不进文件、不进 git"，这条不违反。
- 这里**只连 `hall-packages`**（代码 + 依赖包）。任务中转站 `hall-farm` 由步骤 2 的 bootstrap 自己连
  （它读 `HALL_SHARE_*`），步骤 4 再手工验一次。
- **普通窗口做就行。** 管理员窗口里若报「拒绝访问」，在**那个窗口里**重跑一次同样的命令 ——
  `net use` 建的**无盘符**连接跟登录会话走，提权窗口看得到；**映射盘符（`Z:`）不行**，那个跟进程令牌走（见附录 C）。

**A-1 装 Git。** 一行命令，零依赖，**无外网也能用**：

```powershell
& "\\LAPTOP-VS5F7HF4\hall-packages\repo\install_git.ps1"
```

**应该看到**（结尾三行）：

```
[git-setup] 完成：git version 2.55.0.5.windows.5
[git-setup] 当前窗口还没刷新 PATH，先这样用：& "C:\Program Files\Git\cmd\git.exe" --version
[git-setup] **新开一个 PowerShell 窗口**，git 才直接在 PATH 上。
```

⚠️ **装完必须新开一个 PowerShell 窗口。** 安装程序改了系统 PATH，但**当前窗口不会自动刷新** ——
不新开的话下面 `git config` / `git clone` 都会报「git 不是内部或外部命令」。

**A-2 放行共享盘上的裸仓库（只做一次）。**

Git 把 UNC 路径（`\\机器名\...`）当成"非本地目录"，**不放行就直接失败**：

```powershell
git config --global --add safe.directory '\\LAPTOP-VS5F7HF4\hall-packages\repo\hall-auto.git'
```

没有输出 = 成功。写进的是**全局** git 配置，以后 `git pull` 也受用。

（**第一台真机实测踩到过**：`fatal: detected dubious ownership in repository at '\\...'` +
`'...' may refer to a non-local directory` —— 2026-09-21，明细见 `项目知识库/多机代码分发.md`。）

**A-3 拉代码。**

```powershell
cd C:\Users\你的用户名\Desktop
git clone "\\LAPTOP-VS5F7HF4\hall-packages\repo\hall-auto.git" Huashuo-Dating-Automation
cd Huashuo-Dating-Automation
```

⚠️ **末尾那个目标目录名不能省。** 裸仓库叫 `hall-auto.git`，不给目标名就会落地成 `hall-auto`，
后面每一步的 `cd Huashuo-Dating-Automation` 全部报"路径不存在"。

**应该看到**：`Cloning into 'Huashuo-Dating-Automation'...`，然后文件数跑到 100%。

**这条路为什么是首选**：

- **不要外网、不要令牌、不用登录** —— GitHub 那条三样全要；
- `.gitignore` 自动生效 —— **不会带上老机器的 `config.local.yaml`、`farm_node.env`、`reports\`**，
  这三样正是老路线 C 的坑（见下面「为什么删掉了整包拷贝」）；
- 以后更新只要 `git pull` 一行，不用重新下载整个包。

**报错对照**：

| 报错 | 什么原因 | 怎么办 |
| --- | --- | --- |
| `fatal: detected dubious ownership in repository at '\\...'` | **A-2 没做** —— Git 不放行 UNC 路径 | 照报错里给的那行 `git config --global --add safe.directory '...'` 跑一遍，再重试 |
| `fatal: failed to copy file to '…\.git\objects\pack\…idx': Permission denied` | **共享盘上的文件权限缺 `hallshare`，不是你这台机器的问题。** 报错把路径写成桌面上的目标文件，**那是误导** —— 真因在共享盘那一侧（裸仓库的 pack 文件是从本地目录硬链接过来的，把本地那套权限带了过来，节点账号读不到） | **本机怎么折腾都没用**（换目录、关杀软、清盘全是白费）。把整段报错发给负责人，让他在**共享宿主**上跑 `tools\check_share_acl.ps1`，看到「读不到的：0」之后重试。想自己确认一眼：`Copy-Item "\\LAPTOP-VS5F7HF4\hall-packages\repo\hall-auto.git\objects\pack\*.idx" $env:TEMP\` —— 报"访问被拒绝"就说明是这条 |
| `cd : 找不到路径 ...Huashuo-Dating-Automation` | clone 漏了目标目录名，落地成 `hall-auto` | 删掉 `hall-auto`，回 A-3 带上目标名重跑 |
| `git 不是内部或外部命令` | 装完 Git 没新开窗口 | 关掉重开一个 PowerShell，回 A-2 |
| `找不到网络路径` / 系统错误 53 / 67 / 1326 / **拒绝访问** / 1219 | **共享盘没认证**，或网络不通 | 回 **A-0** 的表逐条对 |
| `fatal: repository ... does not exist` | 共享盘没连上，或共享名写错（先确认 A-0 已过） | 回 A-0。实在不行映射盘符兜底：`net use Z: \\LAPTOP-VS5F7HF4\hall-packages` → `git clone Z:\repo\hall-auto.git Huashuo-Dating-Automation`。⚠️ 这样 `origin` 会记成 `Z:\...`，以后 `git pull` 得先重新映射盘符，**只当临时兜底** |
| 脚本报「找不到安装包」 | 同上，共享盘没认证 | 回 A-0 |
| 脚本报「校验失败，**拒绝执行**」 | 安装包被改过或传断了 | 找组长重新放一份到 `\\LAPTOP-VS5F7HF4\hall-packages\repo\` |

#### 路线 B（兜底）：不下 Git，用系统自带的东西把代码弄下来

**只在共享盘连不上、而这台机器能上外网时用。**

**B-1 浏览器下载（不用令牌，最省事）**：浏览器打开仓库页 → 绿色 `Code` 按钮 →
`Download ZIP` → 解压 → 把文件夹名后面的 `-main` 去掉 → 放到桌面。
前提是浏览器里登录了**有仓库权限的账号**。完整步骤见《新机操作清单.md》步骤六 A。

**B-2 命令行下载（要一个令牌）**：适合这台机器不方便开浏览器的场合。

```powershell
$ProgressPreference = "SilentlyContinue"
[Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12
cd C:\Users\你的用户名\Desktop
$tok = Read-Host "粘贴令牌"

Invoke-WebRequest -Headers @{ Authorization = "Bearer $tok" } `
  -Uri "https://api.github.com/repos/Alvenovo/Huashuo-Dating-Automation/zipball/main" `
  -OutFile repo.zip -MaximumRedirection 5

Expand-Archive repo.zip -DestinationPath _tmp_repo
$inner = Get-ChildItem _tmp_repo | Select-Object -First 1
Move-Item $inner.FullName Huashuo-Dating-Automation
Remove-Item _tmp_repo, repo.zip -Recurse -Force
Remove-Variable tok
Clear-History
Remove-Item (Get-PSReadlineOption).HistorySavePath -ErrorAction SilentlyContinue
```

**为什么用 `api.github.com/.../zipball/main` 而不是 `github.com/.../archive/refs/heads/main.zip`**：
后者是网页端按钮用的地址，**GitHub 的 API 文档里没有它**；前者是官方文档记载的
「Download a repository archive (zip)」端点，对细粒度令牌要求 **`Contents: Read-only`**
（来源：GitHub REST API 文档 "REST API endpoints for repository contents"）。
私有仓库要走有文档保证的那条。

**令牌怎么申请**：细粒度令牌（`github_pat_` 开头），**只给 `Contents: Read-only` 一个权限**，
`Repository access` 勾上本仓库。有预填好权限的直达链接和逐步截图式说明，
见《新机操作清单.md》步骤六 B —— **令牌只显示一次，生成后立刻复制走**。

**报错对照**：`401` 令牌复制不全 / `404` 权限不够（GitHub 会假装"仓库不存在"）/
`403` 令牌过期或 Contents 没给 Read-only。表在《新机操作清单.md》步骤六 B。

**这条路线的三个好处**（也正是老路线 C 的三个坑，见下面「为什么删掉了整包拷贝」）：
- GitHub 打的 zip **不含 `.gitignore` 里的东西** → 不会带上老机器的 `config.local.yaml`、
  不会带上 `farm_node.env`（明文密码）、不会带上 2.8 万个文件的 `reports/`；
- 包体小、解压快；
- 全程只用系统自带组件。

**代价**：拿到的是快照、**没有 `.git`**，以后不能 `git pull` 更新 —— 要更新就重下一次。

⚠️ **令牌是密码级的凭据**：不能写进任何文件、不能贴进聊天或群里。用完清掉命令行历史
（上面最后两行就是干这个的）。

#### 为什么删掉了「整包拷贝」（原路线 C）

原路线 C 是「无外网机器把整个目录打包拷过来」。**已删除**（2026-09-21），两条理由：

1. **它的唯一价值是"无外网也能拿代码"，而共享盘 clone 同样无外网可用** —— 而且更省事：
   增量更新、`git pull` 一行，不用每次重传整个包。
2. **它的三个坑全靠人记得**：必须从压缩包里剔掉 `config.local.yaml`
   （不剔 → 新机器继承老机器的 `C:\Users\<老用户名>\...`，取包失败，
   而**报错长得像"共享盘坏了"**）、`farm_node.env`（明文密码）、`reports\`（几万个文件）。
   `git clone` 下这三样由 `.gitignore` **自动**排除，不依赖人的记性。

**那无外网机器装依赖怎么办？** 不用拷 wheelhouse 了 —— 有网机器产出**一次**放到共享盘，
所有节点自动取：

```powershell
.\.venv\Scripts\python.exe -X utf8 tools\fetch_wheelhouse.py --to "C:\hall-packages\wheelhouse"
```

之后 bootstrap 第 2 步会自己找到它（候选顺序：`--wheelhouse` → 仓库下 `wheelhouse\` →
`installer_dir\wheelhouse` → **共享盘 `hall-packages\wheelhouse\`**），全程不碰网络。
**这件事已经做过了** —— 共享盘上现在就有（12 个 wheel + Python 3.12.10 安装包）。

⚠️ **wheel 是跟 Python 版本绑死的**：`cp312` 的 wheel 装不进 Python 3.13。
测试机上装的 Python 要和产出 wheelhouse 那台**同一个小版本**（现在这份是 **3.12**）。
对不上时 bootstrap 会明确报「wheel 是给 Python 3.12 下的，本机是 3.13 —— 装不上」，
不会丢一堆编译错误给你；**处理办法是把测试机的 Python 换成 3.12**（见「第一部分 · 测试机自己的前置条件」），
不是去改 wheelhouse。
`requirements.txt` 改过之后 wheelhouse 也要重跑，否则 bootstrap 会报「这份 wheelhouse 是旧的」。

> **别拷 `.venv`**（老做法，已废弃）：`pyvenv.cfg` 的 `home` 和 `Scripts\*.exe` 里都写死了
> 原机器的绝对路径，用户名或安装位置一变就起不来，而且**报错看不出来是路径问题**。
> 让新机器用 `wheelhouse` 自己建 venv 才对。

**预期结果**：目录里能看到 `AGENTS.md`、`tools\`、`tests\`、`hall_auto\` 这些文件夹。

**如果报找不到 python**：装 **Python 3.12** 64 位，**安装时务必勾 "Add Python to PATH"**。

### 步骤 2：跑铺环境脚本（**核心步骤，只做一次**）

**第 1 步：先开管理员 PowerShell**（开始菜单右键 → 终端(管理员) / Windows PowerShell(管理员)），
**就在这个窗口里**设共享盘凭据 + 农场目录（**第一行先 `cd` 回仓库根目录** ——
新开的管理员窗口当前目录是 `C:\WINDOWS\system32`，**不继承**你原来那个窗口，
而后面 `tools\...` 全是相对路径）：
```powershell
cd C:\Users\你的用户名\Desktop\Huashuo-Dating-Automation
$env:HALL_SHARE_USER = "hallshare"
$env:HALL_SHARE_PASSWORD = "<共享盘密码>"
$env:HALL_FARM_ROOT = "\\LAPTOP-VS5F7HF4\hall-farm"
```

⚠️ **顺序不能反：先开管理员窗口，再在里面设变量。** 管理员窗口是**全新窗口**，环境变量在里面是空的 ——
你在普通窗口设完再"以管理员身份运行"，那三个变量**一个都不会带过去**。
症状是第 7 步提示「未设 HALL_SHARE_USER/PASSWORD，无法自动连接」、第 10 步取包失败、
`farm_root` 也没落盘。自测：在管理员窗口里敲 `echo $env:HALL_FARM_ROOT`，能打出路径才算设上了。

⚠️ **`HALL_FARM_ROOT` 必须在这一步就设，不是可选项。** bootstrap 第 5 步**只在它存在时**才把农场目录
写进 `config.local.yaml`。这里不设，**配置里就永远是空的** ——
之后这台机器每次开新窗口都得重设，测试机跑 `farm_agent` 会直接打印
「未设 HALL_FARM_ROOT，config.local.yaml 里也没有 farm_root」然后退出。
**注意"跑过 bootstrap"≠"配置里有 `farm_root`"**：判据是当时设没设这个变量（详见第三部分开头）。
（`HALL_SHARE_*` 不设的后果轻一些：bootstrap 第 7 步连不上共享盘，但**它不算失败**，会一直走到取包那步才暴露。）

**第 2 步：同一个窗口里接着跑**：
```powershell
cd C:\Users\你的用户名\Desktop\Huashuo-Dating-Automation
powershell -NoProfile -ExecutionPolicy Bypass -File tools\bootstrap_machine.ps1
```

⚠️ **它会打印两遍，这是正常的，别慌。** 第一次用**系统 Python**跑，只干两件事：
建 `.venv`、装依赖；装完它会**换成 `.venv` 里的解释器把整套重跑一遍**，第二遍才是完整的 13 步。
（为什么要这样：脚本要 import 的 `hall_auto.config` 依赖 PyYAML，而系统 Python 上没有 ——
不换解释器的话，第 5/7/8/10 步会各自"读配置失败"然后**静默跳过**，最后照样打印"全部通过"。
假绿比报错坏得多，所以宁可多打印一遍。第二次跑会在第一次的输出后面接一句
「依赖已就绪。换用 venv 的解释器重跑整套」，看到它继续往下走就对了。）

**（可选）如果这台机器在农场里的名字要用 `R01` 这种编号**，加 `-NodeId`：
```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\bootstrap_machine.ps1 -NodeId R01
```
不指定的话节点名就是**主机名**。这个名字**必须和控制机 `dispatch --nodes` 里写的完全一致**，
否则节点一直报「无任务，退出」—— 看着像控制机没投任务，实际是名字对不上。

**这一步要跑多久？** 第一次大概 5-15 分钟（要建虚拟环境、装依赖、从共享盘拷 400MB 的安装包）。**中途别关窗口**。

**脚本会依次做这 13 件事**（它会自己判断，已经有跳过的，不会重复做）：

| # | 它做什么 | 你要看什么 |
| --- | --- | --- |
| 1 | 环境自检 | 检查系统版本、是不是 64 位 Python、有没有 7-Zip、是不是解锁桌面、**磁盘还剩多少** |
| 2 | 建虚拟环境 + 装依赖 | **先找离线 wheelhouse**（`--wheelhouse` / 仓库下 `wheelhouse\` / 共享盘 `wheelhouse\`），找到就 `--no-index` 装，**完全不碰网络**；找不到才探 pip 源（探不到会立刻提示 + 给绕法，但仍会尝试装）。第一次会装 5 个包，慢是正常的 |

## 第三部分：控制机（你）要做的三件事

**先设农场目录**（**控制机和每台测试机都要**）：
```powershell
$env:HALL_FARM_ROOT = "\\LAPTOP-VS5F7HF4\hall-farm"
```

⚠️ **先说清楚：上面这行只在「这台机器的 `config.local.yaml` 里还没有 `farm_root`」时才需要敲。**

判据是**配置里有没有 `farm_root`**，**不是"跑没跑过 bootstrap"** —— 这两个不是一回事：

bootstrap 第 5 步**只在它运行的那一刻 `HALL_FARM_ROOT` 有值**时才把值写进 `config.local.yaml` 的 `farm_root`。
跑过 bootstrap 但当时没设这个变量 → **配置里依然是空的**，每次开新窗口都得重设。
（2026-09-21 真踩过：**包源机/控制机自己**就是这样 —— 它 12:34 跑过 bootstrap，但当时没设，
于是 `dispatch` 报「未设 HALL_FARM_ROOT，config.local.yaml 里也没有 farm_root」，
而测试机反而有 —— 因为测试机是照着步骤 2 在**同一个管理员窗口里先设变量再跑 bootstrap**的。）

写进去之后 `farm_agent` / `farm_control` 会**自动从配置读**，环境变量只是临时覆盖（比如临时切到别的农场）。
优先级：**环境变量 > `config.local.yaml`**。

**控制机怎么补这一行**（它的 `config.local.yaml` 已在 `.gitignore`，改它不进 git）：

```powershell
# 临时用（只对当前这个窗口生效）
$env:HALL_FARM_ROOT = "\\LAPTOP-VS5F7HF4\hall-farm"
```

要**永久生效**就把它写进配置 —— 最稳的做法是**带着变量重跑一次 bootstrap**
（第 5 步会落盘；bootstrap 幂等，做过的步骤会跳过），或者在 `config.local.yaml` 末尾加一行：

```yaml
farm_root: \\LAPTOP-VS5F7HF4\hall-farm
```

⚠️ **控制机自己就是共享宿主时，更省事的写法是本地路径**：

```yaml
farm_root: C:\hall-farm
```

控制机走 UNC 访问自己的共享，用的是**当前登录身份**，容易撞「拒绝访问」/「找不到网络路径」；
本地路径直接就是本机权限，少一层 SMB 认证。**节点那边照旧写 UNC，两边指向同一个目录，互不影响。**

改完自测（**在仓库根目录敲，不用设任何环境变量**）：

```powershell
.\.venv\Scripts\python.exe -X utf8 tools\farm_control.py status
```

能打出「待执行 N 个，执行中 N 个，已完成 N 个」就是通了；还报同一句就是没写对（注意 UNC 前面是**两个反斜杠**）。

### 3.1 投任务

**参数说明**：
- `--nodes`：测试机的节点名字，逗号分隔。**要和测试机的 `node_id` 对得上**（默认是主机名，也可以用 bootstrap 的 `--node-id` 指定）。
- `--suites`：要跑哪些套件，逗号分隔。**可用套件名单**：

| 套件名 | 跑什么 | 需要什么前提 | 大概多久 |
| --- | --- | --- | --- |
| `unit` | 单元测试（纯逻辑，不碰界面） | 无 | 1 分钟 |
| `install` | 安装/卸载华硕大厅 | **管理员 —— 农场投不了**（见下方警告） | 15-20 分钟 |
| `launch` | 启动冒烟 + 搜索（P0） | 已装大厅 | 3-5 分钟 |
| `apps-detect` | 应用列表检测（只读，不装东西） | 已装大厅 | 3 分钟 |
| `apps-lifecycle` | 真装真卸第三方应用 + 在大厅里点「更新」 | **管理员 —— 农场投不了**（见下方警告） | 10-15 分钟 |
| `login` | 登录 + 注册（P1-B） | **需要测试账号** | 5 分钟 |
| `login-manual` | 短信登录 / 改密码（**人在环**） | 要真人守着。**`dispatch` 会直接拒绝投它** | 5 分钟 |
| `settings` | 主题切换（P1-C） | 已装大厅 | 2 分钟 |
| `security` | 安装包签名验证（P2） | 内部安全工具在（bootstrap 第 8 步自动从共享盘备） | 1 分钟 |
| `wb` | WorkBuddy 入口（P2） | WB 后台开关已开、WB 未安装 | 1-2 分钟 |

⚠️ **`install` / `apps-lifecycle` 走不了农场 —— 投了必挂，别投。**

它们要**管理员权限**，而节点上的 `farm_agent` 是**普通权限**（`is_admin()` 不满足会直接
`pytest.fail`，**不是 skip**）。**也不能把 agent 整体提权** —— 那会改掉 `launch` / `login`
的权限上下文，把别的套件一起搞坏。

所以**全量档 `--suites all` 刻意不含这两个**（理由写在 `hall_auto/suites.py` 的注释里）。
要跑它们，只能在**测试机的管理员终端**里手工跑：

```powershell
cd C:\Users\你的用户名\Desktop\Huashuo-Dating-Automation
powershell -NoProfile -ExecutionPolicy Bypass -File run_p1_apps.ps1      # 夹具装卸 + 在大厅里点「更新」
powershell -NoProfile -ExecutionPolicy Bypass -File run_p0_install.ps1   # 大厅自身装卸
```

⚠️ 这两个脚本**会真装真卸**（`run_p1_apps.ps1` 内部自己设 `HALL_ALLOW_INSTALL=1`），
**只能在测试机上跑，绝不能在办公机**。
⚠️ 它们的结果**不进农场汇总报告** —— 在 `reports\p1_apps_run.log` 和本机 `reports\evidence\` 下。
⚠️ 只想看环境、不装东西，就投 `launch` / `apps-detect` / `settings`。

⚠️ **`login-manual` 投不出去是设计如此，不是脚本坏了**。它要真人在那台机器上收短信、
改密码，投进无人值守农场只会让 agent 卡在等输入、那台机器再也取不到新任务。
要跑它，去**那台机器的交互式终端**里手工执行：
```powershell
.\.venv\Scripts\python.exe -X utf8 tools\farm_agent.py --local login-manual
```

**预期结果**：
```
R01: 2 个套件 -> R01.json
R02: 2 个套件 -> R02.json
...
任务 task_20260918_180000 已投给 5 台节点（共 5 台）。

并发预算：
  launch 全并行（不碰服务端）
  apps-detect 全并行（不碰服务端）
```

⚠️ **那句"并发预算"别忽略**，它告诉你哪些套件被限流了。

### 3.2 叫测试机开跑

**在每台测试机上开跑**（`config.local.yaml` 里已有 `farm_root` 的机器直接敲命令就行）：
```powershell
cd C:\Users\你的用户名\Desktop\Huashuo-Dating-Automation
$env:HALL_FARM_ROOT = "\\LAPTOP-VS5F7HF4\hall-farm"   # 只在配置里还没有 farm_root 时才需要
```
⚠️ **判据是配置里有没有 `farm_root`，不是"跑没跑过 bootstrap"**（这两个不是一回事，见第三部分开头）。
有的话上面那行不用敲 —— `farm_agent` 自己会读。只有临时想切到别的农场时才用环境变量覆盖。
拿不准就直接敲下面的**方式 A** —— `--loop` 启动时会先把「农场目录」「在等哪个任务文件」打出来，
缺配置一样会当场报「未设 HALL_FARM_ROOT…」。

**方式 A（常驻 —— 跑批用这个）**：
```powershell
.\.venv\Scripts\python.exe -X utf8 tools\farm_agent.py --loop
```
每 30 秒去共享盘看一眼，有任务就跑。**跑批期间让这个窗口一直开着。**
⚠️ **要跑批就只能用它。** 关掉窗口 = 后面投的任务全躺在 `tasks\` 里没人取，
而**节点这边一点报错都不会有**，控制机那边只看到「待执行 N 个」永远不动。

**方式 B（一次性 —— 只想跑一轮就走人）**：
```powershell
.\.venv\Scripts\python.exe -X utf8 tools\farm_agent.py --once
```
取一次任务，跑完就退出；**没任务也直接退出**。
⚠️ **它不能用来跑批。** 退出之后没有任何进程再去取任务了 —— 尤其别"先敲它、后投任务"：
任务会一直躺在 `tasks\` 里，看着像"投了没反应"。**只想确认链路通不通**时才用它。

**应该看到**：每 30 秒多一行心跳，长这样 ——

```
节点 R01 农场目录 \\LAPTOP-VS5F7HF4\hall-farm
等待任务文件 \\LAPTOP-VS5F7HF4\hall-farm\tasks\R01.json
[17:12:07] 轮询 #1：无任务，30 秒后再查（等 \\LAPTOP-VS5F7HF4\hall-farm\tasks\R01.json）
[17:12:37] 轮询 #2：无任务，30 秒后再查（等 \\LAPTOP-VS5F7HF4\hall-farm\tasks\R01.json）
```

⚠️ **有这行心跳 = 它是活的，只是在空转，不是卡住**（2026-09-21 前这里是**一片空白**，
新机上真被当成"卡死 5 分钟"上报过，所以现在必须留痕）。

⚠️ **心跳里那个路径要和实际对得上**：控制机 `dispatch --nodes` 写的是什么名字，
这里就该是什么名字。对不上就是**名字写错了**，任务永远取不到 —— 这是「一直无任务」的头号原因。

⚠️ **如果心跳换成了中文排查指引**（`⚠ 节点进程活着，但一个任务都取不到`），
那不是"没任务"，是**真取不到**：按那三条查（包源机关了 / `net use` 不通 / 共享名写错）。

**方式 C（只调试用，不参与跑批）**：
```powershell
.\.venv\Scripts\python.exe -X utf8 tools\farm_agent.py --local launch
```
不走共享盘，本机直接把指定套件跑一遍（`launch` 换成别的套件名即可；需要真人守着的
`login-manual` 也只能这么跑）。
⚠️ **多机跑批期间别开这条** —— 它和农场任务会在同一台机器上抢鼠标键盘，两边都会假失败。

**方式 A / B / C 是同一个脚本的三个模式，不是三个任务** —— 挑一条敲，别连着敲。

**测试机那边的预期输出**：
```
节点 R01 农场目录 \\LAPTOP-VS5F7HF4\hall-farm
取到任务 task_20260918_180000
  跑 launch（分片 1/1）
  跑 apps-detect（分片 1/1）
  证据已回传 \\LAPTOP-VS5F7HF4\hall-farm\results\R01\R01_2026-09-18_1800
任务完成，结果 \\LAPTOP-VS5F7HF4\hall-farm\done\R01_task_20260918_180000.json
```

**出问题时对照**：

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 打印「未设 HALL_FARM_ROOT，config.local.yaml 里也没有 farm_root」后立刻退出 | 环境变量没设，**且这台机器的 `config.local.yaml` 里没有 `farm_root`**。⚠️ 这**不等于**"没跑过 bootstrap" —— bootstrap 第 5 步只在它运行那一刻 `HALL_FARM_ROOT` 有值时才写这一行 | 临时设一次环境变量；要永久生效就按**第三部分开头**那节把 `farm_root` 写进 `config.local.yaml`。**控制机/包源机最容易漏这条**（它是 2026-09-21 真踩过的） |
| 打印「系统错误 67 找不到网络名」 | 农场目录写的是**过期 IP** | 改用机器名：`\\LAPTOP-VS5F7HF4\hall-farm` |
| `--loop` 启动后**长时间没有新输出** | **正常**（2026-09-21 起每 30 秒会打一行心跳；在那之前这里是一片空白，被误报成"卡死"） | 看到 `[HH:MM:SS] 轮询 #N：无任务…` 就是在正常空转。**一行都没有**才是真卡住，看下面两条 |
| 心跳里写 `⚠ 节点进程活着，但一个任务都取不到` | **不是"没任务"，是真取不到** —— 共享盘断了 / 包源机关了 / 共享名写错 | 按心跳里那三条逐条查（① 包源机开着吗 ② 手工 `net use` 通不通 ③ 共享名对不对） |
| 打印「无任务，退出」 | 控制机还没投任务，或者**节点名对不上** | 检查 `node_id` 是否等于 `dispatch --nodes` 里写的名字（`--loop` 的「等待任务文件」那行直接写着它在等哪个文件） |
| `--once` 打印「农场不可达，没取到任务」并返回 3 | 共享盘那边不通 —— **不是"没任务"** | 按紧随其后的中文指引查；别把它当成"链路通了只是没人投任务" |
| 报「拒收任务」 | 同一个 `task_id` 已经跑过了（防重复执行） | 控制机换个 `--task-id` 重投 |
| 报「找不到网络路径」 | 共享没建 / 没认证 | 回开头「⚠️ 开工前必做」那一节，或手工 `net use`（见第二部分步骤 4） |

### 3.3 投任务 / 看进度 / 出报告

**一条命令跑完整批（推荐）**：
```powershell
# ① 先冒烟：一个套件，几十秒，验「节点真的会自己取任务」
.\.venv\Scripts\python.exe -X utf8 tools\run_farm.py --nodes DESKTOP-DOHED68 --suites launch

# ② 通了再跑全量档：7 个套件，几十分钟（--timeout 记得放大，默认 1 小时不够）
.\.venv\Scripts\python.exe -X utf8 tools\run_farm.py --nodes DESKTOP-DOHED68 --suites all --timeout 14400
```
它按顺序做三件事：**投任务 → 每 30 秒查一次进度 → 全部交回执后自动出报告**，中间不用你盯。
⚠️ **冒烟没打出「已交回执」就别投全量档** —— 链路没通，投了只会白等一小时。
⚠️ **冒烟任务不会弹「要不要参与人在环」**（只有全量档才问）。节点终端若停在那句问话上等人回答，
说明节点上的 `farm_agent.py` 是旧的 —— 先在节点 `git pull` 再投。
⚠️ 全量档**不含** `install` / `apps-lifecycle`（要管理员，农场投不了，见 3.1）——
那两块得在测试机管理员终端单独跑，**跑完才算跑全**。
更关键的是：任务投出去 **90 秒还没被取走**时，它会把排查清单直接打出来
（节点 agent 没跑 / 连不到农场目录 / 名字对不上）—— 这正是 `dispatch` 和 `status` 分开敲时
**完全看不出来**的那种卡死：`status` 只显示「待执行 N 个」，而节点侧也一个字都不报。

⚠️ **它不替代节点侧的 `--loop`。** 节点那个窗口没开，它会一直等到超时（默认 1 小时）才退出，退出码 1。
⚠️ 只想投、不想等：加 `--no-wait`（等价于下面那条 `dispatch`）。
⚠️ 中途 Ctrl+C **不丢任务**：节点会继续跑完并写回执，之后 `status` 照样看得到。

下面三条是它内部用的命令 —— **想单独敲、或它出问题时手工顶一下**时用。

**只投任务**：
```powershell
.\.venv\Scripts\python.exe -X utf8 tools\farm_control.py dispatch --nodes DESKTOP-DOHED68 --suites launch,apps-detect
```

**看进度**（随时可以敲）：
```powershell
.\.venv\Scripts\python.exe -X utf8 tools\farm_control.py status
```
**预期结果**：

三个数字的口径：`tasks\*.json` = 待执行 ／ `tasks\*.json.running` = 执行中 ／ `done\*.json` = 已完成。
`dispatch` 只是把任务文件写进 `tasks\`，节点**取走时**才改名成 `.running` ——
**刚投完是「待执行 N 个，执行中 0 个，已完成 0 个」，这是正常的**：

```
待执行 1 个，执行中 0 个，已完成 0 个
  待执行: DESKTOP-DOHED68.json
```

节点取走后（一个轮询周期 30 秒内）变成「待执行 0 个，执行中 1 个」；跑完再变成「已完成 1 个」。

⚠️ **「待执行」超过 30 秒还不降** = 节点上 `farm_agent` 没在跑，或它连不到农场目录。
**控制机这边看不出这个区别** —— 去节点那个窗口看有没有心跳行（见 3.2 那张表）。

**出报告**（全部跑完后）：
```powershell
.\.venv\Scripts\python.exe -X utf8 tools\farm_control.py aggregate
```
**预期结果**：
```
汇总报告：\\LAPTOP-VS5F7HF4\hall-farm\aggregate_report.html
覆盖节点 1 台，用例 N 条
```

⚠️ `覆盖节点` 是**有回执**的节点数（不是投了几台）；`用例 N 条` 取决于投了哪些套件 ——
只投了两个套件时数字会小得多，不是漏跑。

打开那个 HTML，就是最终交付物：一张「节点 × 用例」矩阵表，一眼看出哪台机器挂在哪条用例。

## 第四部分：跑批过程中，测试人员要盯着什么

### 必须做的

| 项目 | 为什么 |
| --- | --- |
| **别锁屏、别合盖、别关显示器** | 锁屏后截图全黑、点击没落点，整批用例假失败。脚本只能保屏幕常亮，管不了你手动锁 |
| **别断 RDP** | RDP 一断，Windows 会话变非交互态，脚本会直接报错退出（这是故意的，比产出一堆假数据好） |
| **别在测试机上手动操作** | 脚本在点鼠标键盘，你一动就会互相干扰 |
| **别关测试机的 agent 窗口**（如果用 `--loop`） | 关了就不取任务了 |
| **确保包源机不关机** | 它一关，正在跑的机器取不到包 |

### 会看到什么现象（正常，别慌）

| 现象 | 正常吗 | 说明 |
| --- | --- | --- |
| 屏幕忽明忽暗 | ✅ 正常 | `settings` 套件在切主题 |
| 大厅自己启动又自己关 | ✅ 正常 | 各套件在跑 |
| 有几个软件被装上又卸掉 | ✅ 正常 | `apps-lifecycle` 在真装真卸夹具应用 |
| 报告里一片黄（skip） | ⚠️ 要看原因 | 看报告「节点环境」表里的**凭据列**：✗ = 这台机器没配凭据（去填 `farm_node.env`）；✓ = 凭据配了，是用例本身在跳过 |
| 汇总时打印「⚠ 这些节点没拿到凭据状态」 | ⚠️ 要留意 | 说明这批结果里凭据列不可信（节点是旧版本、或证据没回传全）。**别拿那一列的 ✗ 当结论**，直接去那台机器看 `farm_node.env` |
| 整批突然停在某个点 | ❌ 要查 | 先看那台机器 `--loop` 窗口**还有没有心跳**：有心跳 = agent 活着、在等下一个任务（去查控制机那边）；**心跳也停了** = agent 挂了或共享盘断了，看测试机的 `farm_root\logs\<节点>_<任务>.log` |

### 绝对不能做的（**点了就出事**）

- **绝对不要在大厅界面上点「全部安装」**。列表里全是 QQ / 微信 / WPS 这类日常软件，点下去就真装一机器。
- **绝对不要把 `install` / `apps-lifecycle` 投给办公机或不归你管的机器**。
  这两个套件一旦被投出去，`dispatch` 会自动带 `HALL_ALLOW_INSTALL=1`，节点会**真卸真装**，
  中间没有第二次确认。
- **绝对不要在办公机上手工设 `HALL_ALLOW_INSTALL=1`**，也不要拿它去"试试看"。
- **别想着把 `login-manual` 硬投出去**（加 `--allow-manual` 能绕过，但除非你正盯着那台机器的屏幕，否则别用）——
  它会卡住那台节点，后面所有任务都进不来。

## 第五部分：跑完之后

1. **收报告**：把 `aggregate_report.html` 发给组长。这是单文件 HTML，不需要别的依赖，双击就能看。

2. **看证据**：共享盘 `results\<节点>\<运行目录>\` 里，`report.html`（本轮报告）和 `summary.json`（给汇总用的）
   **一定有**；**每条用例的**截图 `final.png`（终态截图）+ `result.json` **只在失败时才有** ——
   默认 `--evidence=failure-only`，成功的用例不留图（否则每轮跑批几万张 PNG，盘很快满）。
   ⚠️ 所以「目录里没图」= **本轮全绿**，不是没跑；想连成功也留图，跑批时显式加 `--evidence=all`。

3. **关防火墙**（如果跑批期间为了让共享盘通而临时开的 445）：
   ```powershell
   Remove-NetFirewallRule -DisplayName "HallShare-SMB"
   ```

   ⚠️ 但**如果还要继续跑批就先别关**，一关共享盘就断了。

4. **清下载缓存**：`C:\AsusMCenterDownload` 会堆积安装包（每个几百 MB），定期清理。

5. **别再动测试机**：跑完停在什么状态就是什么状态，下一轮脚本会自己复位。

## 第六部分：出问题怎么查（对照表）

### 测试机侧

| 现象 | 大概率原因 | 怎么解 |
| --- | --- | --- |
| agent 一直说「无任务」，但控制机明明投了 | ①节点名对不上 ②上一轮进程被杀留下 `.running` 占位挡住了 ③**共享盘那边根本没通**（节点只是在报平安） | ①对照 `--loop` 心跳里「等 …\tasks\<名字>.json」那行，和 `dispatch --nodes` 的名字核一遍 ②agent 启动时会自动清残留，重跑一次；还不行就看 `tasks\` 下有没有 `.running` 文件 ③看心跳是不是换成了 `⚠ 节点进程活着，但一个任务都取不到` |
| 控制机说投给 5 台，只有 3 台取到 | 另 2 台网络不通或 agent 没起 | 去那 2 台检查 `net use` 和 agent 进程 |
| 用例大批失败且截图全黑 | **屏幕锁了 / RDP 断了** | 解锁屏幕重跑。这是最常见的原因 |
| 登录用例全 skip | `farm_node.env` 没填凭据 | 填上（见步骤 3） |
| 报「找不到安装包」 | 没跑 bootstrap，还在读假路径 `C:/Users/ASUS/...` | 跑 bootstrap |
| 报「拿不到包，已阻止卸载」 | 共享盘不通 + 没有下载地址 | 检查包源机是否开着、网络是否通 |
| 装到一半失败 | 权限不够 | `install` 套件要管理员 + 计划任务 `HallAutoP1` |
| 找不到 `HallAutoP1` 计划任务 | bootstrap 第 11 步失败 | 用管理员重跑 bootstrap |

### 共享盘侧

| 现象 | 原因 | 怎么解 |
| --- | --- | --- |
| `dir` 没任何输出也不报错 | **目录是空的**，不是失败 | 放个文件再试 |
| 「找不到网络路径」 | 防火墙挡了 445 | 包源机放行 445 |
| 「输入的凭据无效」 | 用了没密码的账号 | 必须用带密码的 `hallshare` 账号 |
| 「拒绝访问」 | 共享权限没给对 | `hall-farm` 要 **Change**，`hall-packages` 要 **Read** |
| `ping` 都不通 | AP 隔离 / 不同网段 | 这条路断了，找 IT |

## 第七部分：一次性准备工作（只做一次，做完全部机器共用）

⚠️ **这一步要人工，而且必须用管理员身份。** 原因是：建 SMB 共享是内核级的特权操作，非管理员进程会报「系统错误 5 拒绝访问」，而且 UAC 那个「是」的确认框画在安全桌面上，非管理员进程根本碰不到 —— 这是唯一绕不过去的硬墙。**但只需按这一次**，5 台机器共用，不用每台都提权。

**在包源机上，用管理员 PowerShell 跑**：
```powershell
cd C:\Users\你的用户名\Desktop\Huashuo-Dating-Automation
$env:HALL_SHARE_PASSWORD = "<共享账号密码>"      # 密码只走环境变量，别写进文件
powershell -NoProfile -ExecutionPolicy Bypass -File tools\provision_share.ps1
```
（也可以写成 `... provision_share.ps1 -SharePassword "<密码>"`，两种都行。
**推荐环境变量**：`HALL_SHARE_PASSWORD` 是节点机 `net use` 用的同一个变量，设一次就够。）

⚠️ **密码必须是 `hallshare` 账号的当前真实密码。** 账号已存在时本脚本只做
「`already exists, left untouched`」——**不会改密码**。随手设一个新密码跑这里，
脚本照样报 `[OK] share account hallshare`，但账号真实密码没变；接着节点机拿这个新密码
`net use` 会报「输入的凭据无效」，全批连不上。忘了原密码就先重置：
`net user hallshare "<新密码>"`，再把 `HALL_SHARE_PASSWORD` 设成同一个值。
**这个密码要一致地用在两处**：包源机跑 provision、每台节点机跑 bootstrap 之前。

⚠️ **管理员窗口是全新窗口**，环境变量在里面是空的，要**在新窗口里重设一遍**再跑。

⚠️ **三行要一起执行，`cd` 不能省。** 不在仓库根目录跑会报
`-File 形式参数的实际参数"tools\provision_share.ps1"不存在` —— 读起来像"脚本没了"，
实际只是当前目录不对。

⚠️ **`hallshare` 账号密码有到期日**（默认 42 天）。到期后所有节点 `net use` 会突然失败，
报错很难认。跑批周期跨月的话，先设成永不过期：
`Set-LocalUser -Name hallshare -PasswordNeverExpires $true`。

**它会做 6 件事**：
1. 确保 `hallshare` 账号存在（不存在就建）
2. 建 `hall-packages` 共享（**Read** 权限）+ `hall-farm` 共享（**Change** 权限）
3. 配 NTFS 权限
4. 放行防火墙 TCP 445
5. 建农场四个目录 `tasks/ done/ results/ logs/`
6. 最后自测一遍网络路径能不能通

**预期结果**（一共 11 行 `[OK  ]`，逐行核对）：
```
[OK  ] share account hallshare
[OK  ] share hall-packages
[OK  ] hall-packages -> hallshare = Read
[OK  ] NTFS C:\hall-packages -> hallshare = Read
[OK  ] share hall-farm
[OK  ] hall-farm -> hallshare = Change
[OK  ] NTFS C:\hall-farm -> hallshare = Modify
[OK  ] farm subdirectories
[OK  ] firewall HallShare-SMB
=== verification (network path, as a node sees it) ===
[OK  ] reachable \\LAPTOP-VS5F7HF4\hall-packages
[OK  ] reachable \\LAPTOP-VS5F7HF4\hall-farm
RESULT: OK
Shares are ready.
```
⚠️ 如果这台机器上共享**早就建好了**，`share hall-packages` / `share hall-farm` 那两行会变成
`already exists -> ... (left as is)`，`firewall` 那行会变成 `already present (left as is)` ——
**都是正常的**，脚本是幂等的。只要末尾是 `RESULT: OK` 就算过。

**退出码**：`0` = 成功 / `2` = 不是管理员 / `1` = 有失败项。

**❗ 报错这样处理**：

| 报错 | 怎么办 |
| --- | --- |
| `RESULT: NOT_ELEVATED`，退出码 2 | 你没用管理员。重新开管理员 PowerShell |
| `RESULT: NO_SHARE_ACCOUNT` | `hallshare` 账号不存在而且你没给密码。设 `$env:HALL_SHARE_PASSWORD` 或加 `-SharePassword "<密码>"` 后重跑 |
| `[FAIL] reachable \\...\hall-farm` | 共享建好了但本机访问不到，通常是防火墙。检查 `Get-NetFirewallRule -DisplayName "HallShare-SMB"` |
| 末尾不是 `RESULT: OK` | 上面一定有 `[FAIL]` 行，按那行的提示处理 |

⚠️ **`hall-farm` 为什么必须给 Change 而不是 Read**：节点要改任务文件名（取走任务）、要写回执、要推证据目录。给 Read 的话这些操作会**静默失败** —— 不报错，但任务永远取不走，你会查到怀疑人生。

## 第八部分：新机器上跑不了的套件（**提前知道，别白折腾**）

新机器铺完环境后，**不是所有套件都能跑**。下面这些要么要额外准备，要么条件不具备：

| 套件 | 新机器上会怎样 | 要什么才能跑 |
| --- | --- | --- |
| `launch` / `apps-detect` / `settings` | ✅ 能跑 | 只要装了大厅（bootstrap + P0 装完后就有） |
| `install` / `apps-lifecycle` | ✅ 能跑 | 管理员 + `HallAutoP1` 计划任务（bootstrap 建好） |
| `unit` | ✅ 能跑 | 无 |
| `login` | ⚠️ 会**静默跳过** | 该机 `farm_node.env` 填了 `HALL_TEST_USER/PASSWORD` |
| `security`（P2） | ✅ 能跑（2026-09-18 起） | 内部安全工具由 bootstrap 从共享盘自动拷；待检安装包按 `installer_dir\<latest_setup>` 找，找不到会回退到 `_cache\`（bootstrap 取回的包就在那）。**若共享盘上没有 `fixtures/security_tools/`，就会 skip** |
| `wb`（WorkBuddy） | ⚠️ 会跳过 | 该机 WB 后台开关已开、且 WB 未安装 |
| `login-manual` | ❌ 永不进农场 | 人在环，只能你在自己终端手动跑 |

**`security` 这条特别说明**：内部工具（CheckAppV / SignAppsV / signcheck_v2）按红线
**不进公开仓库**，但**可以放共享盘**（共享盘不是 git 仓库）。
现在包源机的 `C:\hall-packages\fixtures\security_tools\` 已经放了一份，
bootstrap 第 8 步会自动拷到每台机器的 `<installer_dir>\fixtures\security_tools\`。

所以**新机器上 P2 现在能真跑**，不再是必然黄。只有当共享盘上那份被删了、
或者第 8 步提示「共享盘上没有」时才会 skip —— 那时按提示在包源机补一份即可。

⚠️ 如果你不想让内部工具走共享盘（hallshare 账号能读到），
把 `C:\hall-packages\fixtures\security_tools` 删掉即可，脚本会退化成提示、不判失败，
P2 回到"需要手工拷"的状态。

## 附录 C：几个必须知道的"为什么"

**为什么新机器第一步永远是 bootstrap？**
仓库里默认配置写的是占位路径 `C:/Users/ASUS/Desktop/华硕大厅`，实际不存在的路径。bootstrap 才会把这个路径改成这台机器的真实路径。不跑就找不到包。

**为什么凭据要手填、不自动导出？**
红线是「密码不落盘、不进 git」。自动从环境变量导出到文件，等于把本来是临时的密码写死在磁盘上了。所以脚本只生成一个空模板，落盘这个动作由人显式决定。

**为什么不用映射盘符（`Z:`）？**
映射盘符是跟**进程令牌**绑的，而 `net use \\机器名\共享名` 这种**不带盘符**的连接是跟**登录会话**绑的。
差别很具体：提权（管理员）窗口看不到你映射的 `Z:`，但看得到无盘符连接；计划任务和服务跑在另一个会话里，
两样都看不到。所以：

- **手工连共享盘一律用无盘符形式** —— `net use \\LAPTOP-VS5F7HF4\hall-packages /user:hallshare "<密码>"`（见步骤 1 A-0）；
- **配置里一律写 UNC**（`\\机器名\共享名`），别写盘符；
- 只有 Git 死活不认 UNC 时才临时映射一个盘符兜底。

**为什么共享盘地址写机器名、不写 IP？**
因为 IP 是 DHCP 发的，**会变**。2026-09-18 就真踩过：`config.yaml` 里配的是
`//192.168.0.4/hall-packages`，这台笔记本重启后 IP 变成 `192.168.0.8`，
所有节点立刻报「系统错误 67 找不到网络名」—— 报错看着像"共享没建"，实际是 IP 过期了。
机器名靠 NetBIOS/LLMNR 解析，同一局域网里是稳的（`nslookup` 查不到不代表不能用）。

**为什么内部安全工具能放共享盘，却不能进仓库？**
红线是「不进**公开仓库**」。共享盘在局域网内、要 `hallshare` 账号才能读，
和安装包（未发布的内部版本）在同一个信任边界里。所以放共享盘合规，
bootstrap 就能自动把它备到每台机器 —— 这是把「N 台拷 N 次」压成「1 台拷 1 次」。

**为什么用机器名而不是 IP？**
DHCP 分配的 IP 重启会变，用机器名稳一些（前提是局域网名字解析正常）。
上面「为什么共享盘地址写机器名、不写 IP」那条讲的是同一件事的实例。

**为什么 `login-manual` 套件永远不进农场？**
因为它要真人守着（短信验证码、改密码），无人值守跑不了，硬跑只会卡在 `input()` 上 ——
而且卡住的不只是这一条用例，是**整台节点**（agent 不返回，后面投的任务都取不到）。
所以 `dispatch` 现在**直接拒绝**投它，而不是只打一句警告。要跑就在那台机器上
`farm_agent.py --local login-manual`。

**为什么登录用例没凭据是"静默跳过"而不是"报错"？**
因为设计上允许一台机器只跑不需要凭据的套件。但代价是容易误判 —— 所以报告里专门有「凭据」列来区分「没配凭据」和「用例本身在跳过」，看报告时记得看那列。
